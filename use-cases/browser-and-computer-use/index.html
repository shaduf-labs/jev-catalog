Jev browser use and computer use (TypeSafe AI)

Browser and computer-use agents that let Jev pick the next click, tap or keystroke, read in source. "jev browser use" and "jev computer use" were suggested on Google, Bing and DuckDuckGo when the pool checked on 5 Oct 2026, 05:14 UTC. A suggestion shows that people search for something; it does not show how many. This page reads seven agents that act in a browser, on a phone or on a Mac, plus one shopping extension that only recommends. For each it shows whose session the agent uses, what leaves the page, and whether it still clicks, types or submits when Jev errors, gives a bad or unsure answer, has no key, or is skipped. The pool ran none of them: no agent, no extension, no Jev call.

Key finding

Of 7 Jev browser and computer-use agents read in source, none clicks or types when Jev errors, but 5 act on low-confidence answers, and only 1 asks a person before send, buy or delete.

Documentedsource at pinned commits, checked 5 Oct 2026

Picked from the plan's leads, three GitHub searches and the 24-hour scan, preferring exact name matches with a real Jev call path; not a survey. 8 counted, 1 excluded as a mock by default (how they were chosen). The counts describe these 7 agents at these commits, with default settings, and nothing more.

What happens when Jev fails, by situation

Open a situation to highlight its column. Opening one closes the others. Failure terms use the pool's shared vocabulary: fail-closed (stops with no action), fail-open (acts anyway), fallback-<what> (a named substitute), no-decision (returns nothing; the caller must handle it) and no-threshold (no confidence cut, so any answer is acted on). Below-threshold cells are never added to error cells. Retries and status codes are on Jev API errors, limits and retries.

The Jev call failsHTTP error or timeout

0 of 7 agents still act: all 7 are fail-closed. Timeouts are 25 s (jev-ultrafast, ironbee-express, jev-android), 30 s (jev-agent-browser) and 60 s (computer-use-jev). Jev for Chrome and Ulka set no timeout: a hung call waits rather than acts. second-look shows a heuristic verdict instead (fallback, recommendation only).

Malformed answerMissing or invalid fields

0 of 7 act directly on a malformed answer. In 1 of 7 (jev-agent-browser) a missing or invalid target goes to a word-overlap resolver, and the action then runs on the target it picks. computer-use-jev re-reads the screen and asks again on a bad target, without acting.

Jev is unsureLow confidence

5 of 7 act on any confidence (no-threshold). 2 of 7 stop with no action below a cut: jev-android at 0.65 (a default the caller can set per task; it replans twice, then reports BLOCKED) and computer-use-jev at 0.5 for click, fill, type, press and activate. Neither hands the item to a person, so these are no-decision, not held. Choosing a cut: how to choose a confidence threshold.

No API keyJev cannot be called

6 of 7 refuse to act. ironbee-express replays a cached recording if one exists, and nothing judges it; without a recording it refuses. jev-agent-browser opens its --url start page before the key check (navigation only). Testing without a key: testing a Jev integration without an API key.

Ways around JevPaths that skip the Jev call

Recorded in 4 of 7: ironbee-express (cached replays and an LLM takeover after a stall, budget limit or BLOCKED), jev-agent-browser (regex label overrides, in classify mode only), computer-use-jev (passthrough mode runs raw tool calls, including click, with no Jev and no key) and Ulka (cached actions and a forced first action, both still behind the approval gate). Not recorded in 3 of 7.

second-look: a shopping adviser that never acts

second-look (0c05d16, created 4 Oct 2026) is a Chrome side-panel extension that gives one verdict on a product page. It has no click, submit or form-fill code: the pool searched its extension files for .click(), dispatchEvent, submit( and executeScript and found only content-script injection. A person buys. It is counted as a browser row on the when-Jev-fails checklist, but not in the counts of 7 acting agents on this page. Documented

On a Jev error, a timeout (15 s), a malformed answer or no key, second-look still shows a verdict. The fallback is "WAIT" if a fake discount was detected, otherwise "BUY_NOW", with confidence None. Before you let a Jev agent drive your browser, phone or Mac

  • Your logged-in session is the agent's session. 5 of 7 agents act in the user's own Chrome, phone or Mac session by default, with whatever logins and payment methods it holds. Prefer a fresh profile (ironbee-express does this by default) for anything you do not watch. Documented
  • Page content leaves your machine. Every agent sends page or screen text to Jev: up to 6,000 to 18,000 characters, with field values in 3 of 7 (jev-ultrafast, Jev for Chrome, Ulka). All 7 exclude or mask password fields. Other personal data on the page is sent. Read what data leaves your system. Documented
  • Unsure is not the same as failed. All 7 agents stop on a Jev error, but 5 of 7 act on low-confidence answers because they set no threshold. See how to choose a confidence threshold. Documented
  • Irreversible actions. 1 of 7 (Ulka) asks a person before send, submit, buy or delete. If you build one, add a fixed-rule or human gate before these actions, and do not rely on Jev's confidence alone. Tool-call guards in coding agents are compared on Claude Code and MCP.
  • Speed and benchmark claims are Reported. An AndroidWorld result comes from arXiv 2609.30186, "Jev-Mobile: Jev as an Executor for Mobile GUI Agents", by a single author, submitted 24 Sep 2026 per arXiv. It is the author's claim; the pool did not run it and states no figure. jev-ultrafast's speed claims are the project's README claims. Reported
