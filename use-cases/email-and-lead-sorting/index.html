Jev email classifier (TypeSafe AI): what each Gmail and lead sorter does to your inbox when Jev fails or is unsure

"jev email classifier" was Google's first suggestion for the words "jev email" when the pool checked on 3 Oct 2026, 05:22 UTC. A suggestion shows that people search for something; it does not show how many. Bing, DuckDuckGo and YouTube offered no Jev email suggestion. This page reads the source code of five public projects that sort email or sales leads with Jev. It compares what access each asks for to your mailbox, what it does without asking you, what it sends to Jev, and where an email ends up when Jev fails or is unsure. It then works out the cost per 1,000 emails and ends with seven design rules.

Key finding

Of 5 email and lead sorters read in source, none touches the mailbox when Jev errors; of the 3 that can write to Gmail or IMAP, only 1 routes unsure mail to a Review label.

Documentedsource at pinned commits, checked 3 Oct 2026

Projects picked by stars from a GitHub search for 'jev email OR jev gmail OR jev inbox' (59 results, 3 Oct 2026), plus one lead-qualification project found that day. Not a survey; stars are not adoption (how the five were chosen). All five are code-backed integrations. The pool installed none of them, connected no mailbox and made no Jev call. None of the five has been independently confirmed as working in real use.

What the five projects add up to

Who can touch your mailbox, and who asks first

Two of the five only ask for read-only Gmail access. The three that can write do not ask you about each message. Documented source, 3 Oct 2026

  • Read-only: JevmailAsks only for gmail.readonly. The code says: "Never add gmail.modify, gmail.labels, or mail.google.com here". It sorts emails into lanes inside its own app database, so Gmail itself never changes.
  • Read-only: spam-leadgen-pipelineAsks for gmail.readonly and reads the spam folder. Without asking you, it writes classifications and a qualified flag for each sender to a Supabase database. According to the README, outreach is drafted elsewhere Reported.
  • Writes, preview by default: ilyamkAdds labels, and archives only in one mode for a spam rule at confidence ≥ 0.93. Preview is the default, and jobs run only when you start them from its interface. Its Gmail scope is not declared in the repository.
  • Writes, live by default: parth-kpLogs in over IMAP with an app password, which gives it full mailbox access. It can tag, move, flag, mark read or unread, and call a webhook. If you run jev-mail with no arguments, it acts on the mailbox straight away. Dry-run is opt-in.
  • Writes on a timer: vynnleeAsks for the full https://mail.google.com/ scope, which would also allow permanent deletion. It labels, stars and, in archive mode only, archives. Once switched on, it runs on a timer and does not ask about each message.

Five projects: where an email goes when Jev fails or is unsure

Open a situation to highlight its column and read what the five do. Opening one closes the others. Every cell comes from source at the commit shown. Failure terms use the pool's shared vocabulary: fail-closed (stop, refuse or take the cautious outcome), fail-open (act anyway), advisory (flag only), fallback (a stated substitute outcome), no-decision (no result, no action). Documented Read 3 Oct 2026, 05:19–05:25 UTC

The Jev call failsHTTP error, rate limit or timeout

None of the five changes the mailbox. Three stop or pause the run: ilyamk, parth-kp and spam-leadgen. vynnlee retries the thread later with backoff. Jevmail leaves the email unclassified and retries it on the next run. Repeated 429 responses pause that run, and a 403 stops it. Jevmail, ilyamk and vynnlee set no HTTP timeout in code.

Jev is unsureLow confidence or below the threshold

Of the 3 that write: vynnlee puts the email under a "Review" label and leaves it in the inbox. ilyamk makes a second, full-body call and then applies that answer's label without checking confidence again; archiving is still gated at 0.93. parth-kp does nothing, but marks the email as processed, so it is never checked again. Jevmail only flags the email; spam-leadgen marks the sender as not qualified.

Malformed answerUnknown category, missing fields, bad probabilities

2 of 5 check the answer strictly before acting: ilyamk and vynnlee. Jevmail turns an unknown category into "promotional". parth-kp raises an error on a missing answer but does not check that probabilities lie between 0 and 1, so a value of 1 or more would trigger actions.

No API keyand ways around the Jev call

Four refuse to run without a key. For spam-leadgen this was not determined: it creates the official SDK client with no arguments, and how the SDK behaves without a key was not read. Jevmail's /preview is a simulator that makes no Jev call.

Data and permissions

  • Emails are personal data, both about the sender and about the mailbox owner. All five send subject text or sender details to Jev, and 4 of 5 send the sender's address (parth-kp does not). Work through the data checklist before connecting a real inbox.
  • Mailbox access requested: vynnlee asks for the full https://mail.google.com/ scope. parth-kp has full IMAP access through an app password. Jevmail and spam-leadgen ask for gmail.readonly. The scope ilyamk is granted is unknown, because the repository has no appsscript.json manifest. Sorting by label alone needs neither full access level.
  • The route changes which data terms apply. As checked on 3 Oct 2026 at 05:16 UTC: Jevmail calls Vercel AI Gateway, whose only listed Jev endpoint is DigitalOcean with has_zdr: false (Vercel route). ilyamk calls OpenRouter, whose TypeSafe endpoint is on OpenRouter's zero-data-retention list (OpenRouter route). Cost per 1,000 emails

Jev's price is $0.042 per million input tokens, and output is free. Documented TypeSafe models page, rechecked 3 Oct 2026, 05:16 UTC. OpenRouter, Vercel and Cloudflare list the same price. New accounts get no free credit (access status), so even a first test on 1,000 emails is charged at this price.

Pool arithmetic on the documented price

Assumptions, made by the pool and not by TypeSafe: about 4 characters per token for English text, because TypeSafe does not publish a ratio in the pages read. Plus 500 tokens per call for the question text, because the pages read do not say whether question text is billed as input. The maximum assumes every email reaches the project's body limit.

Documented price pool arithmetic

Show one calculation (Jevmail)

2,000 body + ~200 header characters ÷ 4 = ~550 tokens, + 500 for the question text = ~1,050 tokens per email. 1,000 emails × 1,050 = 1.05 million tokens × $0.042 = ~$0.044.

Seven rules for sorting email with Jev, and which projects follow them

  1. Ask for the narrowest mailbox permission.

    Sorting by label does not need https://mail.google.com/ or full IMAP access. 2 of 5 work with read-only access.

    Jevmail, spam-leadgen: read-onlyvynnlee, parth-kp: full accessilyamk: unknown
  2. Send unsure mail to a visible "Review" label and keep it in the inbox.

    This is better than applying a label anyway or skipping the email for good.

    vynnleeilyamk: labels anywayparth-kp: never re-checked
  3. On a Jev error, change nothing in the mailbox and retry later.

    All 5 already change nothing in the mailbox; keep it that way. How to handle rate limits is on errors and rate limits.

    All 5
  4. Check the answer before acting on it.

    Accept only known categories and probabilities between 0 and 1.

    ilyamk, vynnleeJevmail: unknown becomes "promotional"parth-kp: no range check
  5. Cut the body before sending.

    A limit caps both the cost and the amount of personal data sent.

    4 of 5parth-kp: no cut
  6. Start in preview or dry-run mode, and keep a log of actions.
    ilyamk: preview by defaultparth-kp: live by default, no log
  7. Treat outbound actions as irreversible.

    Put stricter checks on webhooks and CRM writes than on labels.

    parth-kp: webhookspam-leadgen: lead records without confirmation

These rules are a design reading of the source code above, not a measured result. How to set thresholds: confidence thresholds.

How the five were chosen and read

On 3 Oct 2026 at 05:19 UTC, a GitHub repository search for "jev email OR jev gmail OR jev inbox" returned 59 results. That is a count of indexed repositories, not of users. The four with the most stars were read: fazlerocks/jevmail (93 stars), ilyamk/jev-gmail-ai-spam-filter-and-labeling (22), parth-kp/jev-mail-classifier (19) and vynnlee/jev-mail (10). The pool added automatewithuday/spam-leadgen-pipeline (0 stars, created 2 Oct), the one lead-side project with a Jev call path found in that day's 24-hour scan. A second search, "jev lead OR jev crm OR jev outlook" (8 results), found Outlook sorters but no lead-scoring or CRM project. This is a reading order, not a sample: stars do not measure how many people use a project.

Each project was pinned to one commit and read from source. The runner read Jevmail. It was audited on 28 Sep from its moving main branch and is now pinned at f6f20af (last commit 19 Sep, so the classifier has not changed since then). A helper agent read the other four. The runner then spot-checked them against the raw files at the same commits at 05:25 UTC, without re-reading every line. Nothing was installed or run, no mailbox was connected and no Jev call was made.

Not read: atomiclabs-tech/atomic-inbox (no Jev call path at aa7d056), anshulkhare7/jev-gmail-triage (its description says it labels mail with an LLM through OpenRouter), withoneai/mastra-inbound-router (a lead-routing candidate, not reached in time) and 50+ smaller repositories. Email demo videos are in the email videos group.

What was not verified

  • The OAuth scope ilyamk is actually granted: the repository has no manifest.
  • How spam-leadgen behaves without a key, and which model it uses: both are decided inside the SDK, which was not read.
  • HTTP timeouts for Jevmail, ilyamk and vynnlee: none is set in code, so platform defaults apply, and those were not checked.
  • Whether question text is billed as input, and how many characters make a token. Both are assumptions in the cost table.
  • The inputs behind the demo's "1,700 emails for $0.18".
  • The four projects read by the helper agent were spot-checked, not re-read line by line. The line references in the sources below allow each cell to be checked.
  • How any of the five behaves in real use: none was run, and none is confirmed as working. How many people use them is also unknown.
