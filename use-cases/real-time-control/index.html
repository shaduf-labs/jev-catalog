Jev plays Doom: what real-time demos do when a Jev call fails

Jev plays Doom (TypeSafe AI): real-time game and robot demos, and what each loop does when Jev fails. Three game and robot-simulation demos that call Jev, read at pinned commits: what Jev decides, the loop tick, the request timeout, and what each loop does on an error, a bad answer or no key. Two more harnesses are listed for contrast and are not counted. "jev plays doom" and "jev doom demo" were suggested on Google, Bing and DuckDuckGo when the pool checked on 12 Oct 2026, 05:16 UTC. A suggestion shows that people search for something; it does not show how many. The pool ran nothing: no game, no simulation, no Jev call. Every cell comes from code read at a pinned commit.

Key finding

Of 3 published game and robot-simulation demos that call Jev, read at pinned commits, 2 keep their last action when a call fails (doom-jev, JevPlaysSnakeGame) and 1 stops (jev-robotics-demo); none is a product.

Documentedcode read at pinned commits, checked 12 Oct 2026, 05:19 UTC

The 3 are the counted rows in the harness table: 2 + 1 = 3, and all 3 are runnable demos. Two were read on 11 Oct 2026; the third is one of two harnesses read on 12 Oct from four leads screened that day. This is not a survey of game or robot demos. Keeping the last action means the loop goes on acting on a choice Jev did not make for this tick, so when Jev fails counts it as "action goes ahead".

Failure terms use the pool's shared vocabulary: fail-closed (stops with no action), fallback-<what> (a named substitute, here the last action or "wait"), no-decision (nothing is decided; the caller must handle it) and no-threshold (no confidence cut, so any answer is acted on). Patterns to copy

  1. Keep the last action when a call fails. doom-jev (bd4e98f) catches the error and the game keeps applying the last action every tic (brain.py L331–334; game.py L193, L287). JevPlaysSnakeGame (b9237bf) returns nothing and the snake keeps its direction (src/agents/jev_agent.py L62–64; src/game/engine.py L127–128).
  2. Set the timeout against the tick and drop late answers. doom-jev (bd4e98f): 2.0 s timeout, no retries, at most 5 requests in flight, stale answers dropped (brain.py L291, L301–302, L340–352). Contrast: llm-invaders (dfcbc49) applies late answers with no staleness check (play.py L99–100).
  3. Let ordinary code run the fast loop; ask the model for slower strategy. ra2web-jev-player (0e4e8cf): the 150 ms loop has no network calls; the model is asked every 1.5 s (game.py L1–13; config.py L30). Not counted: it calls a local substitute by default.
  4. Reflexes that override the model. doom-jev (bd4e98f): shoot and stop-at-wall reflexes (game.py L255–281). jev-robotics-demo (531de61): a simulation filter for unsafe moves and a hand reflex (jev_agent.py L215–218, L266–273).
  5. A call budget with a scripted fallback. ra2web-jev-player (0e4e8cf) switches to scripted play after 1,200 cloud calls (jev/client.py L114–116; game.py L223–226).

What not to copy

  • An uncaught exception that stops the loop. jev-robotics-demo (531de61) has no try in jev_agent.py, so one failed call, bad answer or missing key ends the run. The pool counts this as fail-closed: the demo stops and no action is taken.
  • A blocking call inside the tick with the SDK's default timeout. JevPlaysSnakeGame (b9237bf) sets no timeout, so the SDK 0.7.4 default (10.0 s, 2 retries) applies to a game that ticks at most 10 times per second (src/agents/jev_agent.py L56; config.yaml L2). The game waits; it does not act on a late answer.
  • Applying answers with no staleness check. llm-invaders (dfcbc49) applies an answer whenever it arrives (play.py L99–100), up to its 30 s timeout. In its benchmark this delay is measured on purpose (invaders/harness.py L28–39).

Retries and status codes: Jev API errors, limits and retries. Choosing a cut: how to choose a confidence threshold.

Counting and mapping judgements

These calls were made by the pool, not read from the code. The counting rule is the pool's decision of 12 Oct 2026.

  • llm-invaders is not counted. Its own code applies the move, but no model player is the default: bench.py requires --players (L66) and play.py defaults to "human" (L124). It also calls Jev through OpenRouter, not TypeSafe's API.
  • JevPlaysSnakeGame is counted. main.py runs the Jev agent unconditionally (L12) with the SDK's default URL and model, and its own code moves the snake.
  • ra2web-jev-player is not counted. It calls a local substitute ("clef-flash") by default.
  • "Keep the last action" counts as "action goes ahead" on when Jev fails: the loop keeps acting on a choice Jev did not make for this tick.
  • llm-invaders error and malformed cells are fallback-wait, not no-decision, because "wait" is one of the game's actions.
  • doom-jev's malformed-answer cell is an inference from the 11 Oct read: there is no validation, and the error stays inside the per-request task.
  • JevPlaysSnakeGame's bypass cell ("none found") covers src/game/engine.py L96–151 only.
  • JevPlaysSnakeGame's no-key cell rests on typesafe-sdk 0.7.4 (the version the demo locks) raising a catchable error for a missing key (read 11 Oct).
  • jev-robotics-demo's no-key and timeout cells are the values for typesafe-sdk 0.7.x; the demo does not pin the SDK version.
  • ra2web-jev-player's no-key cell is an inference from the 11 Oct read.

Not verified

  • The pool ran no harness, package or API call. Every cell comes from code read at a pin; none is an observed runtime behaviour, and no tick or timeout was timed.
  • JevPlaysSnakeGame snake.py was not read (for example, whether a reversal is rejected).
  • llm-invaders engine.py was not read (whether "fire" does nothing when no shot is ready), and its results files were not opened.
  • snowu/jev-fighter (Jev only with a configured key; the hosted build uses a local brain) and Jayman391/ROS-JEV-LLM (default backend not found in the files read, 12 Oct 2026, 05:13 UTC) were screened, not read.
  • Harness leads from the 12 Oct scan (for example romantic28/jevGameAgent and yuki-uchida/moq-games) were not read.
  • No TypeSafe-published real-time harness was found among the typesafe-ai GitHub organisation's repository names or its cookbook folders on 11 Oct 2026, 05:18 UTC; not rechecked on 12 Oct.
