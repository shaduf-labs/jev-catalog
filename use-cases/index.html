What can you build with Jev (TypeSafe AI)? Use cases by evidence level

Jev is useful for one bounded decision inside a larger workflow: route this ticket, hold this comment, pick this page element. This page lists the patterns found so far, with the evidence behind each and what goes wrong when Jev is wrong or unavailable.

Short answer

The best-evidenced patterns are email sorting, comment moderation, trade entry gates, browser action selection, UI composition, agent tool-call guards and support-ticket routing (five projects read on 1 Oct): the pool read the code that calls Jev in each. Vendor documentation adds moderation, retrieval, citation checks and fixed-set function selection. None of these patterns has an independently verified production deployment, and the three audited projects handle Jev failures in three different ways.

Does your task fit?

  1. You can list the answers in advance (queues, labels, yes/no, a 2–10 level rubric).
  2. Your code, not Jev, performs the action and checks permissions.
  3. You have a path for low-confidence answers and API errors: a rule, another model or a person.

If any answer is no, read Limitations and fit check first; it has an interactive version of this test and the 17 weaknesses TypeSafe documents for Jev 1.13 (arithmetic, dates, long irrelevant context and others). To see these patterns running, use the demo videos, grouped by the same use cases.

Which of these tasks has published accuracy tests?

Some patterns above have been measured by third parties. The results are on the graded benchmarks ledger, each with operator, task, sample size, baseline and grade. All are Reported; the pool ran no benchmark.

  • Jev as an LLM judge or evaluator (hallucination checks, preference pairs, summary quality): B02 Arize and B08 CMU. Both find Jev close to a frontier LLM judge on verdicts that can be read off the text once a threshold is tuned; B08 finds it behind on math, code and logic.
  • Model or tool tier routing: B05 LiteLLM (80 authored prompts; grade C, the operator ships Jev as a router option).
  • Retrieval passage selection and reranking: B14 Elastic (e-commerce search, grade A provisional).
  • Email sorting: B12 Bryo (German and English business email, grade C).

For choosing between Jev, an LLM and a trained classifier for your task, see Jev vs an LLM vs a classifier.

What happens when Jev fails: three audited projects

The 28 September audit read the code paths of three projects that call Jev. Each handles an API error, a missing key, a malformed answer and a low-confidence answer differently. Before copying a project, decide which of these behaviours your own task can accept. Documented source code read 28 Sep 2026

What was not verified

  • No pattern on this page was run by the pool, and no accuracy figure is established for any of them.
  • No audited project was observed running in production. Creator timing and cost figures are their own reports.
  • Project README rows were not checked against source code in the run where they were recorded.
  • Main-branch links can change after the check date; the audit did not pin commits.
