What can you build with Jev (TypeSafe AI)? Use cases by evidence level

Jev is useful for one bounded decision inside a larger workflow: route this ticket, hold this comment, pick this page element. This page lists the patterns found so far, with the evidence behind each and what goes wrong when Jev is wrong or unavailable.

Short answer

For 14 patterns the pool read the code that calls Jev: email and lead sorting (five projects read on 3 Oct), comment moderation (six projects read on 2 Oct), trade entry gates (four bots read on 4 Oct), fraud and payment checks (three gates read on 4 Oct), Jev as an eval judge (four tools read on 4 Oct), browser and computer use (seven acting agents read on 5 Oct), UI composition, an agent completion check, agent tool-call guards, support-ticket routing (five projects read on 1 Oct) model routing (six routers read on 2 Oct), reranking and passage filtering for RAG (five implementations read by 8 Oct), and SQL row judgments and document splitting (five projects read on 8 Oct). Vendor documentation adds marketplace moderation, citation checks and fixed-set function selection. None of these patterns has an independently verified production deployment, and the projects read handle Jev failures in different ways. Across 69 implementations in 11 use cases, on a Jev error 38 stop or hold the action, 15 fall back, 8 let it through unchecked, 5 return no decision and 3 are advisory (when Jev fails: all use cases compared, 8 Oct; eval judges counted from 7 Oct, rerankers and document pipelines from 8 Oct).

Does your task fit?

  1. You can list the answers in advance (queues, labels, yes/no, a 2–10 level rubric).
  2. Your code, not Jev, performs the action and checks permissions.
  3. You have a path for low-confidence answers and API errors: a rule, another model or a person.

If any answer is no, read Limitations and fit check first; it has an interactive version of this test and the 17 weaknesses TypeSafe documents for Jev 1.13 (arithmetic, dates, long irrelevant context and others). To see these patterns running, use the demo videos, grouped by the same use cases.

Which of these tasks has published accuracy tests?

Some patterns above have been measured by third parties. The results are on the graded benchmarks ledger, each with operator, task, sample size, baseline and grade. All are Reported; the pool ran no benchmark.

  • Jev as an LLM judge or evaluator (hallucination checks, preference pairs, summary quality): B02 Arize and B08 CMU; what judge tools do when Jev fails is on Jev as a judge. B02 finds Jev level with Claude Opus 5 once cutoffs are tuned on half the data; B08 finds it "within three points of GPT-6 wherever a verdict can be read off the text" and behind on math, code and logic. B06 Jevals adds yes/no, intent and score tasks graded against human labels.
  • Model or tool tier routing: B05 LiteLLM (80 authored prompts; grade C, the operator ships Jev as a router option). What routers do when Jev fails is on model routing.
  • Content moderation: no published accuracy test was found (content moderation).
  • Retrieval passage selection and reranking: B14 Elastic (e-commerce search; reranking-pipeline study, grade B, not rerunnable at 250 queries; grade A provisional until 7 Oct). Every reranking study by type (relevance-judgment or reranking-pipeline), with grade and conflict-of-interest flags: Jev reranker and Jev for RAG.
  • Email sorting: B12 Bryo (German and English business email, grade C).

For choosing between Jev, an LLM and a trained classifier for your task, see Jev vs an LLM vs a classifier.

What happens when Jev fails: three audited projects

Compare all use cases: when Jev fails counts what 69 implementations in 11 use cases do on a Jev error, a malformed answer, an unsure answer, a missing key and a bypass (recomputed 8 Oct 2026, with two rerankers, a prompt filter and two document pipelines added). The table below is the original 28 Sep audit.

The 28 September audit read the code paths of three projects that call Jev. Each handles an API error, a missing key, a malformed answer and a low-confidence answer differently. Before copying a project, decide which of these behaviours your own task can accept. Documented source code read 28 Sep 2026

What was not verified

  • No pattern on this page was run by the pool, and no accuracy figure is established for any of them.
  • No audited project was observed running in production. Creator timing and cost figures are their own reports.
  • Project README rows were not checked against source code in the run where they were recorded.
  • Main-branch links in the 28 Sep rows can change after the check date; that audit did not pin commits. The WordPress row is now pinned at d848a5b, Jevmail at f6f20af (3 Oct), QuantDinger at a5a9f4c (4 Oct; its 28 Sep line links had gone stale), and the support, email, routing, moderation, trading and judge pages use pinned commits.
