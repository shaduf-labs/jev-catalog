Evidence standard

A verified product entry needs a direct source for Jev use and a separate direct signal that the project operates beyond a local, mocked, or reference setup. A named product or organisation, public deployment that can be checked, case study, package or deployment record in use, or reproducible production trace can provide that second signal. A README, SDK dependency, directory listing, screenshot, or star count alone cannot.

Application

Direct Jev wiring

The source calls or wraps Jev and shows how the answers enter the application. This establishes integration, not adoption.

Demo or harness

Bounded execution

Mocks, fixtures, local/Docker paths, and reference runners are useful for learning. They do not establish production operation.

Verified product

Separate operation evidence

The source must support operation beyond the repository and identify the product or organisation. No checked lead meets this bar.

Adoption boundary: no checked direct source names a paying customer, operator, case study, production trace, package release in use, or independent usage measure for these leads. No authenticated Jev call was made in this audit. The page records source-level integration and deployment metadata only.
