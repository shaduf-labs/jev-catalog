Jev n8n node (TypeSafe AI): official vs community nodes, and what each does when the Jev call fails

"jev n8n" was offered as a search suggestion by Google and by YouTube on 3 Oct 2026, 05:24 UTC; Google also offered "jev n8n github". A suggestion shows that people search for the phrase, not how many do. Several n8n nodes for Jev are on npm, and two of them share the name n8n-nodes-typesafe-ai. This page shows which one TypeSafe publishes, which one runs on n8n Cloud, and what five nodes, read in source, do to your workflow when the Jev call fails.

Key finding

Only the scoped @typesafe-ai/n8n-nodes-typesafe-ai is TypeSafe's (npm provenance, n8n-verified); the unscoped n8n-nodes-typesafe-ai is a third party's. All 5 nodes read stop the workflow on a Jev error by default.

Documentednpm provenance and source at pinned commits, checked 3 Oct 2026

With Continue On Fail on, 3 of the 5 can send a failed item down a real branch unless a fallback output is set. The five are the official node and four community nodes picked from 15 Jev and TypeSafe n8n packages found on npm, preferring packages with a public repository (see how the five were chosen). Not a survey. The pool installed none of them and ran no workflow.

Which one to install

Both packages below use the name n8n-nodes-typesafe-ai. The only difference in the name is the @typesafe-ai/ scope in front. The npm records show who publishes each. Documented npm registry records and SLSA attestations, read 3 Oct 2026, 05:20–05:21 UTC; maintainer lists re-read 05:27 UTC

Correction to earlier pool pages

Earlier pool notes compared the GitHub tag 0.9.0 with the npm package n8n-nodes-typesafe-ai 0.1.1 as if they were one package, and the official vs reseller page said only that the npm publisher had not been checked. They are two packages from two publishers. The official one is the scoped @typesafe-ai/ package.

Can you use it on n8n Cloud?

n8n's documentation says: "Unverified community nodes aren't available on n8n cloud and require self-hosting n8n." n8n's public community-node listing had 1,765 entries when read on 3 Oct 2026, 05:27 UTC. The only Jev or TypeSafe entry was @typesafe-ai/n8n-nodes-typesafe-ai 0.9.0, marked as an official node and listed on 2 Oct 2026, 11:44 UTC. None of the four community nodes read for this page is listed, so on n8n Cloud only TypeSafe's node is available of these five. Documented

"n8n declined verification": one maintainer's claim

The maintainer of n8n-nodes-jev-classification (khmuhtadin, not one of the five read) wrote on the n8n forum on 26 Sep 2026: "n8n declined verification in September 2026 because of overlap with the built-in classification node that is in progress." n8n has not confirmed this. It does not show that n8n rejected any other node. Reported

What happens to your workflow when the Jev call fails

In all five nodes, n8n's "Continue On Fail" setting decides whether a Jev error stops the workflow or is passed on as an item. Choose a setting to see what the five nodes do with it; the matching column in the table below is outlined. Documented source at pinned commits, read 3 Oct 2026, 05:20–05:23 UTC; the official node's routing re-checked by the runner at 05:27 UTC

Continue On Fail

Off: 5 of 5 nodes stop the workflow

  1. 1. An item reaches the Jev nodeThe node sends the item's text (or the fields you chose) to Jev.
  3. 2. The Jev call failsFor example the official node throws NodeApiError on any HTTP status of 300 or more.
  5. 5The workflow stopsOfficial, DomMonte, n8n-nodes-jev, taifoon and zampierid4p all throw. No item is sent down a decision branch.

This is the behaviour the key finding calls "by default": no item is routed. If Jev returns 429, the official node does not retry by itself; its README tells you to turn on n8n's "Retry On Fail".

On: where the failed item goes

  1. 1. An item reaches the Jev nodeContinue On Fail is on.
  3. 2. The Jev call failsThe node turns the error into an item instead of stopping.
  5. 3A real decision branch, unless a fallback output is setOfficial: Fallback or Uncertain output if configured, else the first route, the lowest Score level or Noul "False". n8n-nodes-jev: Low Confidence output if enabled, else the first route. zampierid4p: question 1's branch.
    1A Review outputtaifoon: the error item, with the key redacted and the input fields dropped
    1An error object onlyDomMonte: one output with {error, description}; the input fields are dropped and nothing is routed

So with Continue On Fail on and no fallback output configured, the failed item arrives on a branch that real answers also use, such as Noul "False" or your first route. The official node and n8n-nodes-jev add an error field to that item; zampierid4p drops the input fields.

What the five rows add up to

Four rules for using a Jev node in n8n

  1. Install the scoped @typesafe-ai/n8n-nodes-typesafe-ai if you want TypeSafe's node.

    Not the unscoped n8n-nodes-typesafe-ai. Before installing any node, check its npm maintainer and provenance. More on telling official surfaces apart: is this Jev site official?

    official: scoped, provenanceDomMonte: same name, no scope
  2. Leave Continue On Fail off, or turn on a fallback output with it.

    If you turn it on, also enable the Fallback (Choice) or Uncertain (Noul) output, or route errors to n8n's error output. Otherwise a failed Jev call can land on your first route or on "False". How n8n's error output handles this is known only from the official node's code comment.

    official, n8n-nodes-jev, zampierid4p: real branch possibletaifoon: Review output
  3. Set the timeout on purpose.

    The official default is 5 s. If you use the official node, add n8n's "Retry On Fail" for 429s; the node does not retry. Rate limits and retry advice: errors and rate limits.

    5 s or 60 s2 nodes: not set
  4. Send only the fields Jev needs.

    Avoid "Input Item" and whole-item modes for personal data. What leaves your system on each route: data handling by route.

    taifoon: whole item by defaultofficial, n8n-nodes-jev: if chosen

The rules are a design reading of the source above, not a tested result. None of the five nodes documents pinned test data; for testing failure paths without a key, see testing without a key.

How the five were chosen

The official node, typesafe-ai/n8n-nodes-typesafe-ai, was read at tag 0.9.0 (commit c12537b, the repository's only tag; last push 29 Sep 2026, 21:11 UTC). The four community nodes were picked from npm registry searches for "n8n-nodes jev", "n8n typesafe" and n8n community-node packages with the keyword "jev" (3 Oct 2026, 05:20–05:22 UTC), preferring packages with a public repository. That is a reading order, not a sample, and the 15 found is not a survey of all Jev n8n nodes. Each node was read from raw files at one pinned commit by a helper agent briefed with the table's columns; the runner spot-checked the official node's error routing, both npm maintainer records and the n8n listing against the same sources. No node was installed, no package was unpacked, no workflow was run and no Jev call was made. Repository stars were not fetched.

The query phrase comes from Google suggest ("jev n8n", "jev n8n github") and YouTube suggest ("jev n8n"), both at 05:24:12 UTC; Google also offered "typesafe n8n github" and "typesafe n8n example" for "typesafe n8n". Bing and DuckDuckGo gave no Jev n8n suggestion. A video tutorial, "How To Setup JEV With n8n", is in the n8n videos group.

Other no-code tools: Zapier

Zapier lists a "TypeSafe Jev" app with one action, "Ask Questions" (checked 5 Oct 2026, 05:21 UTC). Documented The page does not say who built it and shows no date. Failure behaviour is not readable in source (Zapier is a closed platform): not recorded. It is not counted here or on when Jev fails.
