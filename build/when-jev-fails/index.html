When Jev fails (TypeSafe AI)

What do real Jev implementations do when Jev returns an error, a malformed answer or an unsure answer, when no API key is set, or when a code path skips Jev? This page counts the answers across 71 implementations in eleven use cases, already published row by row on their domain pages, and turns them into an eight-question checklist for your own code. The title is an internal label: six failure phrases ("jev fallback", "jev timeout", "jev error handling", "jev fail open", "jev retry", "typesafe api error") got no relevant autocomplete suggestion on Google, YouTube, Bing or DuckDuckGo when the pool checked on 4 Oct 2026, 05:21 UTC.

Key finding

Of 71 Jev implementations read in source, on a Jev error 38 stop or hold the action, 17 fall back, 8 let it through, 5 return no decision and 3 are advisory. The 8 that let it through are 4 moderation bots, 2 agent hooks, a passage filter and an eval tool.

Documentedrecomputed from 11 domain tables, checked 10 Oct 2026

The eval tool is openlayer jevals: its report counts an errored eval as passed and its gate allows by default. Counting 7 fallbacks that can still end in the action as well, the action goes ahead on a Jev error in 15 of 71 (8 fail-open plus 7 fallbacks; details).

The 2 agent hooks are danna-zhou/jev-mcp for Claude Code and jev-judge for Hermes Agent, in enforce mode (its default is shadow).

Implementations were picked per domain page as stated there, not as a survey. The counts describe these 71 implementations at their pinned commits; they are not a rate for Jev integrations in general. "Not recorded" means the domain page and its research note do not record the cell; it is never inferred. n = 71 in every count. The official TypeSafe Claude Code plugin makes no runtime Jev call, so it is excluded from every denominator; the trycua/cua jev-use example calls a mock provider by default and is not counted either. Judge tools count from 7 Oct 2026: a judge whose own code turns Jev's answer into a score, pass/fail or gate is an action (an error that becomes a pass is fail-open; a dropped item is no-decision). The four judge tools on Jev as a judge form the LLM as a judge domain. The Jevals harness on Jev as a judge is not counted: its code is not public, so its failure cells are Reported from its methodology page, not read at a pinned commit. From 8 Oct 2026 a reranker counts when its own code reorders or cuts results, and a document pipeline when its own code acts on Jev's answer: LiteLLM's compaction guardrail, jev-reranker and LanceDB's TypeSafeReranker are counted under Frameworks (see Jev reranker and Jev for RAG), pg-redact under Content moderation and docjev under Email and lead (see Jev inside SQL and document pipelines). These are nearest domains: no new domain reached 3 rows. The three SQL extensions are listed but not counted. n8n nodes are counted with Continue On Fail (COF) off, the default; the COF-on result is given beside them. The pool ran nothing for this page: no bot, no browser agent, no eval, no Jev call.

Both do nothing until switched on: jev-approvals is off after install (core default manual), and jev-curator observes by default. Their cells describe the switched-on modes.
  • 7 Oct: settled without a count change: rh-guard's default mode is enforce; opencode-tool-gate's "action goes ahead" holds under OpenCode's default rules (v1.18.35: every tool allowed); osuki checked at 0.2.8, failure path unchanged.
  • 8 Oct: five rows added under the 8 Oct rule (a reranker counts when its own code reorders or cuts results; a document pipeline when its own code acts on Jev's answer). LiteLLM's TypeSafe compaction guardrail, jev-reranker and LanceDB's TypeSafeReranker go under Frameworks, where the Spring AI passage filter and the LlamaIndex reranker already sit; pg-redact (PII redaction before storage) under Content moderation; docjev (document splitting) under Email and lead.   • 8 Oct, three counting choices (manager decision): LiteLLM's compaction guardrail is counted although the results it removes are tool outputs, not retrieved passages (without it n would be 68); pg-redact's malformed cell is fail-open (a missing span answer stores the span unredacted; a broken body gives 502); openlayer's no-key cell is fallback-another backend (it fails closed if no other backend is configured).
  • 8 Oct, corrected: jev-approvals no longer counts as fail-closed on a Jev error. On a timeout, connection error, 429 or 402, Hermes core v2026.9.24 hands the approval question to the main agent model, which can approve the command; only other HTTP errors still go to a person. It moves to fallback and into the "action goes ahead" line. Also filled on 8 Oct: jev-curator's malformed (fail-closed), below-threshold (held) and no-key (fail-closed) cells, and openlayer's no-key cell. rh-guard's below-threshold text was clarified (0.5 is Jev's choice confidence; REVIEW_THRESHOLD 0.45 is a risk-label floor); its term is unchanged.
  • 10 Oct: two coding-agent rows added (manager decision). jev-effort-router is a routing fallback, like osuki: on a Jev error, a wholly malformed answer or no key the request is left untouched and the turn runs on the operator's configured model, so it is not in "action goes ahead". Below its 0.5 cut the code rewrites the request to deepseek-v4.1-flash at medium effort (fallback-default model). jev-gateway passes the request to the agent's own model on a Jev error, a malformed answer or an unsure answer; that model picks the tool and the call runs, so jev-gateway is one of the 7 fallbacks that can still end in the action. Its below-threshold cell is fallback-agent's own model, not acts-anyway, because Jev's answer is not used. With no key the gateway does not start (fail-closed). jev-triage and hermes-jev-mana were read on 10 Oct but are not settled on coding agents, so they are not counted here.
  • Listed but not counted: the three SQL extensions on Jev inside SQL and document pipelines (pg-jev, sqlite3-jev, sqlite-jev). Their value goes back into your query, which decides what to do with it; a Jev error still aborts the statement, as that page shows.

Eight questions to ask of your own Jev integration

Apply each question to your own code. The counts show how the 71 answered it; the chips link to example rows on the domain pages. Chip colours: green holds or stops, red acts anyway, blue falls back, amber is advisory.

  1. When Jev errors or times out, does the action still happen?

    38 of 71 stop or hold it. 8 let it happen unchecked: 4 content-moderation bots, 2 agent hooks (danna-zhou for Claude Code, jev-judge for Hermes), the Spring AI passage filter and openlayer jevals, whose report counts an errored eval as passed. None of the 7 browser agents clicks or types on a Jev error. 17 of 71 fall back (in 7 of them the action can still happen), 5 of 71 return no decision, 3 of 71 are advisory; not recorded 0 of 71.

    jev-judge: fail-open in enforce modeWordPress Jev Comment Triage: holds, retries, then a persondanna-zhou/jev-mcp: the command runsSpring AI JevDocumentFilter: unscreened passages keptopenlayer jevals: errored eval counted as passedjev-ultrafast: "no action executed"
  2. What is your timeout, and what happens when it fires?

    Timeouts set in code range from 0.40 s (btc-hft-jev) to 180 s per task (DeepEval JevEval). Some set none: jev-for-chrome and Ulka have no request timeout. Coding-agent hooks and providers use 1.2 s (rh-guard) to 25 s (the two Hermes plugins; Hermes core's own default is 30 s). Timeouts were not tallied across all 71. Status codes and retries: errors and rate limits.

    btc-hft-jev: 0.40 s, then rules-onlyjkudish/jev-mcp: 60 s, error to the agent
  3. If Jev answers in the wrong shape, do you treat it as "no" or as "yes"?

    11 of 71 let the action go ahead on a malformed answer (pg-redact stores a span unredacted when its answer is missing). 1 more (jev-agent-browser) guesses a target by word overlap and clicks it. 33 of 71 fail closed; 19 of 71 fall back (openlayer reads a non-numeric answer as 0.5); 3 of 71 are advisory; 3 of 71 return no decision; not recorded 2 of 71. Validate before acting.

    fraud-jev: a non-numeric probability → allowjev-trader: any answer other than "sell" → buygbesse/zammad-jev-triage: checks model, option and probability
  4. What happens when Jev is unsure?

    16 of 71 hold unsure items: 13 send them to a person or a review queue, jev-curator refuses the change, and 2 (LiteLLM's compaction guardrail and jev-reranker) drop the result or passage below their cut. 15 act anyway below their cut, including pg-redact, which stores the span unredacted. 18 have no threshold at all, including 5 of the 7 browser agents and 3 of the 4 judge tools. 9 of 71 fall back, 4 of 71 are advisory, 4 of 71 return no decision; not recorded 5 of 71. Choosing a cut: confidence thresholds.

    vynnlee/jev-mail: Review labelgbesse: review groupbackmeupplz/jev_antispam_bot: below 0.81, kept
  5. What happens with no API key?

    35 of 71 refuse to start, error or hold the call. 4 proceed as if allowed: WordPress triage, the danna-zhou hook, ironbee-express when it replays a cached recording, and jev-judge. 11 fall back to another backend or LLM, a mock, a heuristic, the host's own permission rules or the unchanged request (jev-effort-router). 18 not recorded. 3 of 71 are advisory. Test it: testing without a key.

    WordPress triage: WordPress's own decision standsdanna-zhou hook: proceedsjev-fraud-shield: mock
  6. Which code paths never ask Jev?

    38 of 71 have a recorded bypass, including passthrough and replay modes in 4 browser agents, the off header of jev-gateway, read-only or permission-request-only paths in 2 coding-agent gates (opencode-tool-gate, jev-kit), the off or observe modes of the 2 Hermes plugins, and empty-input shortcuts that skip the call in the 5 rows added on 8 Oct. Not recorded 33 of 71. List yours: exits, allow-lists, admin users, kill switches, "mock" modes.

    jev-trader: the mock model trades without Jevbackmeupplz: group admins' messages skippedJevmail: /preview simulator, no mailbox actioncomputer-use-jev: passthrough mode clicks with no Jev and no key
  7. Is your fallback cheaper or riskier than failing?

    17 of 71 fall back to another model, scorer, rule set, default or the unchanged request on a Jev error. jev-approvals hands the approval to the main agent model, which can approve the command. jev-gateway passes the request to the agent's own model, which picks the tool, and the call runs. second-look shows "Good deal — buy it" from a heuristic when Jev is unavailable. Not recorded 0 of 71.

    0xNatoshi/jev-codex-router: bills the frontier model on every Jev failureQuantDinger: asks an LLM, then allows
  8. Is the failure written down, and does a failed log write block the action?

    Not counted across the 71: the domain tables have no logging column. Record every failure with its reason.

    QuantDinger: logs "audit persistence skipped" and continuesjev-trader: writes its log after the order is sentBillionsBobby/JevRouter: attaches provider_errorSpring AI JevDocumentFilter: logs a WARN with the number of unscreened passages
