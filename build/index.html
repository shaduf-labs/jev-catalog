Build with Jev (TypeSafe AI): choose Python, TypeScript, HTTP, Claude Code or a gateway

This hub helps you pick the code interface for your stack and then work through a build in a sensible order: make the call, decide what happens when it fails, test the failures, and set a confidence cutoff. Route prices and data terms are on Where to use Jev, not here.

Short answer

Python backends should use typesafe-sdk 0.7.2. TypeScript projects choose between @typesafe-ai/sdk 0.6.0 and the AI SDK's experimental experimental_evaluate. Any other language can use one HTTP POST. If you are adding Jev to a coding agent, read the failure behaviour of the integration before installing it. The two official SDKs retry 408, 429 and 5xx twice and accept an injected transport for tests. Raw HTTP and most agent integrations have no retries. Documented package sources and docs; versions checked 29 Sep 2026

Build steps, in order

Each step has its own page. The projects and guards the pool has audited differ most in steps 2 and 3: what happens when the call fails, and whether that path is tested (counted across 7 use cases on when Jev fails).

  1. Make one call

    Pick the interface above and run a single Choice, Score or Noul question with a pinned model ID.

    Python · TypeScript
  2. Decide the failure policy

    For each decision, choose fail closed, hold for review, or fail open, and which status codes to retry. Check your code against what 39 real implementations do.

    Errors and rate limits · When Jev fails (checklist)
  3. Test the failure branches

    Drive no key, 401, HTML 403, 422, 429, 529, timeout, malformed and out-of-set answers without a key.

    Testing without a key
  4. Set the confidence cutoff

    Choose where low-confidence answers go, using your own labelled data.

    Confidence thresholds

Adding someone else's guard to a coding agent skips step 1 but not the others: check its failure policy on Claude Code and MCP before you rely on it.

What this hub does not cover

  • No code path listed here was run against the live Jev API; the pool has no key. Only the offline mock-server clients (T01 Python, T04 Node) were run.
  • Prices, credits and data terms are on the Access and cost pages. Framework libraries have no build page yet; n8n nodes are on Jev n8n node (3 Oct).
  • Versions change often: the Python SDK went from 0.5.7 to 0.7.2 in two weeks. Check the date on each row.
