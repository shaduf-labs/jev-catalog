How to use Jev with Codex, OpenCode, Cursor and Hermes Agent (TypeSafe AI)

Does your coding agent's tool call or model choice still go ahead when Jev fails? 10 Jev integrations for Codex, OpenCode, Cursor and Hermes, in code. This page answers one question for each Jev plugin, hook and MCP server for coding agents: when the Jev call fails, does the agent's tool call still run? When the pool checked search suggestions on 6 Oct 2026, 05:19 UTC, Google suggested "how to use jev with codex" and "how to use jev with opencode", and "jev hermes" appeared on Google, Bing and DuckDuckGo. Rechecked on 10 Oct 2026, 05:17 UTC: "jev codex" completes to "jev codex router" on Google, Bing and DuckDuckGo, and "jev hermes" to "jev hermes agent" or "hermes agent jev"; no new host phrase appeared on two endpoints (R12-S11). A suggestion shows that people search for a phrase, not how many do.

Key finding

Of 22 integrations read in source, 10 act on Jev's answer, 10 do not and 2 are unsettled. On a Jev error the 10: 3 hold, 1 may ask the main model, 5 let the call run, 1 keeps its configured model.

Documentedsource at pinned commits, checked 10 Oct 2026, 05:12–05:20 UTC; the 8 earlier counted rows unchanged from 7–8 Oct

Picked from the plan's list, the Hermes Agent catalog, three GitHub searches, the pool's daily scans and, on 10 Oct, 3 pinned reads chosen by host priority from 35 scan leads; not a survey. The 22 are coding-agent integrations. Of the 22, 1 is vendor-published (OpenClaw's plugin), 21 are community projects (personal repositories and 1 npm package) and 0 come from TypeSafe. The pool installed and ran nothing: no agent, hook, plugin, proxy or MCP server was started and no Jev call was made. npm tarballs were downloaded and read, not executed.

  • 3 hold the tool call: jev-kit, bloudhood's Codex approval hook and jev-curator (guard mode).
  • 1 may ask the main model: jev-approvals hands the question to Hermes's main agent model on a timeout, connection error, 429 or 402 when a main provider is set, and that model can approve the command; other errors go to a person.
  • 5 let the call run: rh-guard (conditional), opencode-tool-gate, osuki, jev-judge (enforce mode) and jev-gateway, where the agent's own model picks the tool.
  • 1 keeps its configured model: jev-effort-router, a model-choice row; the turn runs on the operator's configured model and effort.

3 + 1 + 5 + 1 = 10 counted. 10 not counted (8 return Jev's answer to the agent, 2 give advisory hints) and 2 not settled (jev-triage, hermes-jev-mana): 10 + 10 + 2 = 22.

2 of the 10 (jev-approvals, jev-curator) do nothing until you switch them on. jev-approvals is off after install: Hermes core's default approval mode is manual, so you must set approvals.mode: smart. jev-curator runs in observe by default: Jev does not block anything until you change the mode to guard or apply. Two more start in a softer mode: jev-judge only logs (shadow) until you switch on enforce, and osuki uses Jev only if you pick TypeSafe as its decision provider. jev-effort-router has routing on in its defaults but is inert until OPENROUTER_API_KEY is set, and acts only when the provider is Ollama:Cloud. jev-gateway routes by default once a launcher points the agent at it.

Install-and-check list

Six questions to answer before you rely on any of these. Documented from the rows above, 10 Oct 2026; 22 integrations, 10 counted, 10 not counted, 2 not settled. Cells (a) to (e) still not recorded in the counted table: 0 of 50

  1. Who publishes it? 1 of 22 comes from the host vendor (OpenClaw's plugin). The other 21 are community projects (personal repositories and 1 npm package). 0 of 22 come from TypeSafe.
  2. Which mode does it start in? jev-approvals is off after install (Hermes core default manual; set approvals.mode: smart); jev-curator starts in observe and blocks nothing until you set guard or apply; jev-judge starts in shadow (log-only); typesafe-skill-router starts off. rh-guard starts in enforce, so a default install can block. jev-effort-router and jev-gateway route by default once a key is set.
  3. What happens with no key? Unset the key and try a risky call. jev-kit, bloudhood and jev-approvals ask you; jev-curator (guard mode) blocks the background deletes and patches it guards; jev-gateway does not start; rh-guard, opencode-tool-gate, osuki and jev-judge (enforce mode) let it through or fall back; jev-effort-router leaves the turn on your configured model (3 + 1 + 1 + 4 + 1 = 10). For jev-approvals, also make Jev time out: Hermes then asks its main agent model, which can approve. Test procedure: testing without a key.
  4. Which tools never reach Jev? Read the matcher. bloudhood covers Bash, apply_patch and mcp__ only; rh-guard's Codex matcher has no MCP tools; jev-approvals sees only commands Hermes flags as dangerous; jev-curator sees only background skill deletes and patches.
  5. Is the catalog commit the one you read? Three Hermes catalog entries install a commit other than the repository's HEAD, and jev-curator is in a different repository from the one recorded on 5 Oct (pins below).
  6. What leaves your machine? See the next section.
