How to use Jev with Codex, OpenCode, Cursor and Hermes Agent (TypeSafe AI)

Key finding

Of 27 coding-agent integrations read in source, 14 act on Jev's answer, 10 do not and 3 are unsettled. On a Jev error those 14 are 3 fail-closed, 9 fallback and 2 fail-open (pinned source; failure-map terms, 21 Oct 2026).

The 27 are coding-agent integrations. Of the 27, 1 is vendor-published (OpenClaw's plugin), 26 are community projects and 0 come from TypeSafe. The pool installed and ran nothing: no agent, hook, plugin, launcher, proxy or MCP server was started and no Jev call was made. npm tarballs were downloaded and read, not executed; jcode's source was read at its pinned commit and not built or run.

  • 3 fail-closed: jev-kit, bloudhood's Codex approval hook and jev-curator (guard mode) hold the tool call.
  • 9 fallback, each to a named path: opencode-tool-gate to OpenCode's permission rules; osuki to its default tier; jev-gateway to the agent's own model, which picks the tool; jev-approvals to Hermes's main agent model on a timeout, connection error, 429 or 402 when a main provider is set (that model can approve the command; other errors go to a person); rh-guard to its lexical detectors; and 4 model-choice or routing rows: jev-effort-router (configured model), jev-triage (main model, OpenClaw), the jev-for-all launcher (default tier: standard, claude sonnet, medium effort) and hermes-jev-mana (original Hermes branch).
  • 2 fail-open: jev-judge (enforce mode) and ohmyjev's pi and omp adapters let the call run.

Does the tool call still run on a Jev error? Yes in 5 of 14 (2 fail-open, 3 fallback: OpenCode's permission rules, the default tier, the agent's own model), conditionally in 2 (both fallback), no in 3 (fail-closed). The other 4 are model-choice or routing rows (fallback): the turn runs on another model.

3 fail-closed + 9 fallback + 2 fail-open = 14 counted; 5 yes + 2 conditional + 3 no + 4 routing = 14. 10 not counted (8 return Jev's answer to the agent + 2 give advisory hints) and 3 not settled (Hoppin-Sorter/jev-router, auto-mode, jcode): 14 + 10 + 3 = 27. To compare your own design with the 80 implementations on the failure map, use the failure self-check.

3 of the 14 (jev-approvals, jev-curator, hermes-jev-mana) do nothing until you switch them on. jev-approvals is off after install: Hermes core's default approval mode is manual, so you must set approvals.mode: smart. jev-curator runs in observe by default: Jev does not block anything until you change the mode to guard or apply. hermes-jev-mana is inert after the documented install: every Jev call is refused because admit_unlabeled defaults to false; it acts only if the operator sets admit_unlabeled: true. Two more start in a softer mode: jev-judge only logs (shadow) until you switch on enforce, and osuki uses Jev only if you pick TypeSafe as its decision provider. jev-effort-router's routing is on in the plugin's own config, but the plugin is off until it is enabled in Hermes; with Hermes defaults (model "") it is inert, because it acts only when the provider is Ollama:Cloud (R13-S217). jev-gateway routes by default once a launcher points the agent at it. jev-triage is on at startup and acts where Jev is the agent's decision model. The jev-for-all launcher acts only when you run jev-for-all start. ohmyjev's pi and omp adapters deny the calls they flag from install and never add a prompt (its README, Reported).
