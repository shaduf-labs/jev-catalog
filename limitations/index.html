What Jev (TypeSafe AI) cannot do: documented limits and a task fit check

Jev answers typed questions from a fixed answer set. Tasks that need free text, raw images (an opt-in experiment since 14 Oct 2026, not production-ready per TypeSafe), exact arithmetic or an answer outside the list you gave it are a poor fit. This page lists the 17 limits TypeSafe documents, with its workaround for each, has a three-question check you can run on your task, and shows which SDKs and integrations send images to Jev.

Short answer

TypeSafe documents that Jev 1.13 is weak at literal-versus-intended reading, arithmetic and counting, date comparison, multi-step questions, long irrelevant state and adversarial text. It cannot generate text, takes no audio or video, and works best in English. Input is text by default; since 14 Oct 2026 images can be sent only as an opt-in experiment that TypeSafe says is not production-ready (checked 16 Oct 2026, 05:21 UTC). The limits listed here were written for Jev 1.13; TypeSafe has not published a separate limits page for the Jev 1.14 preview. Keep computation, permissions and actions in your code, and use Jev to pick among options you define, score against a rubric, or estimate a yes probability.

Is Jev multimodal?

Text by default; images only as an experiment. TypeSafe's models page lists the input of both Jev 1.14 and Jev 1.13 as "Text". Images are accepted only when you send the opt-in header TypeSafe-Danger-Zone-Images: true; TypeSafe says images and Box questions "aren't yet up to our standards to call ready for production". So image input is experimental and not production-ready per TypeSafe. There is no audio or video input. (Models page and images page, checked 16 Oct 2026, 05:21–05:22 UTC.) Documented

TypeSafe's post on Jev 1.14 says jev-1.13.0 "was multimodal all along". Reported No image was sent here, so image quality is not tested.

pydantic-ai-slim 2.56.0 and 2.57.0 reject a request with images before any call is made (UserError('TypeSafe does not support image input.'), models/typesafe.py L219–220; package files read 16 Oct 2026, nothing run). So the experimental image input is not reachable through that package. For comparison, OpenAI's Decisions API and Cloudflare's Clef take images; Microsoft-Decision-1 is text only (OpenAI and Microsoft read 13 Oct 2026, Cloudflare 12 Oct 2026; see the input row of the decision-API comparison and their rows on Alternatives). More on the 1.14 changes: what changed with Jev 1.14.

Key finding

Of 8 integrations read, 5 send images to Jev and 2 of those add TypeSafe's opt-in header for you; pydantic-ai refuses images, and both LangChain packages pass them as text.

What TypeSafe's docs say about image requests

Images page and models page read 23 Oct 2026, 05:19 UTC (re-read 05:26 UTC, byte-identical); API reference read 05:23 UTC. Documented

Status
"Images and Box questions aren't yet up to our standards to call ready for production, but we're excited for dreamers and builders to play with them. … The request format, the answers, and the limits on this page can change between releases" (images page).
Opt-in header
"Images and Box questions are off by default. To use them, send the TypeSafe-Danger-Zone-Images: true header with each request that contains an image or a Box question." The API reference lists it as an HTTP header parameter.
Which versions
The images page says "Jev 1.13 and Jev 1.14 both accept images. Box questions need Jev 1.14." The models page still lists the input of both versions as "Text" and says Jev "reads natural-language text … It does not accept audio or video". Both are quoted as published; the two pages are not reconciled here.
Formats
"png" | "jpg" | "jpeg"; "PNG or JPEG, still images only. Animated PNGs are rejected." The format is detected from the bytes.
How an image is sent
Inline data_base64 ("no data: prefix") or as a multipart file part. An image URL field is not stated on the images page, the errors page or the API reference (05:23–05:26 UTC); the asset schema has type, format, data_base64 and part only.
Limits
16 MiB per image file; 280 to 1568 pixels per side; 78,400 to 2,458,624 pixels in total; request body 32 MiB; all images 32 MiB after processing; expanded request 32 MiB. "An image outside them is rejected, never resized to fit. If any image in a request is rejected, the whole request fails: there are no partial answers." No fixed image count is given.
Errors
400 without the header ("Images are not turned on"; no error name given); 400 for a rejected image or asset (not PNG or JPEG, damaged, animated, too small, invalid base64 or format, an unreferenced asset); 400 max_tokens_exceeded when images and text exceed the context length; 413 over a size limit. The errors page does not mention images.
Billing
"Each image counts as input tokens, billed at the same per-token input price as text. There is no separate charge for images."

Sources: TypeSafe images page L9, L19, L61, L79–83, L158, L183, L327–337, L365, L371–378 (R22-S100); models page L16, L22 (R22-S101); API reference, System One L46–53, L371–372 (R22-S103); request rules and errors (R22-S102).

A route that lists image input is a listing; it does not show that the route forwards TypeSafe's opt-in header. Each route's image field, read 23 Oct 2026, is on versions and aliases; whether OpenRouter, Vercel, Opper, Netlify or Cloudflare forward or add the header is not known.

Fit check: does your task fit?

What the three questions test

QuestionWhy it mattersTypeSafe's own guidance
1. Can you list the possible answers in advance?Choice takes up to 255 named options, Score an ordered rubric of at least 2 and at most 10 levels, Noul a yes/no question. Jev cannot return an answer you did not offer. Arithmetic and date comparison belong in code, not in the question."System One models do not write replies, produce code, or generate explanations of their reasoning. You define the possible answers through primitives." System One concepts
2. Will your own code decide what happens after the answer?A valid answer can still be wrong. In the audited projects the action policy lives in the calling code and differs a lot between projects."code owns the workflow and AI handles narrow, structured decisions … Keep control flow, deterministic rules, and side effects in code." How to build with System One
3. What happens when Jev is unsure, wrong or unavailable?Errors happen (401, 422, 429, 529 are documented). One audited trading gate lets an entry through when Jev fails; a moderation plugin holds the comment instead. Of six moderation projects read on 2 Oct, four leave the post up when Jev fails (content moderation). For a Noul, the middle band of probabilities is the "unsure" zone."Low confidence: Do not act. Route to a human, request clarification, or fall back to a different system." Confidence page

Documented Quotes checked 28 Sep 2026. The check runs entirely in your browser: it sends nothing, calls no model and stores nothing. It gives a starting recommendation, not an accuracy estimate. To measure accuracy on your own cases, see Confidence thresholds; for real examples, see the failure matrix.

When to use something else

  • You need generated text or code: an LLM, optionally with structured output.
  • You have thousands of labelled examples and a stable label set: a trained classifier may be cheaper and local; see alternatives.
  • You need the model to run on your own hardware: independent open-weight models, with their own licences and accuracy; see alternatives.
  • The rule can be written exactly (a regex, a threshold, a lookup): write the rule.

For a full comparison with 10 criteria (labelled data, changing labels, text output, latency, residency, probabilities, input length, arithmetic and language, volume, vendor risk) and the published head-to-head results, see Jev vs an LLM vs a classifier: when to use which. What published tests found for each task type is on the benchmarks ledger.

What was not verified

  • This pool did not test any limit by calling Jev; every row is TypeSafe's own documentation.
  • How often each weakness occurs on a real task is not measured here. The only published non-English test with a baseline is Bryo's German and English email benchmark (grade C, B12). TypeSafe's jaggedness page still said "Last reviewed 2026-09-17" on 30 Sep 2026.
  • Gateway-specific limits beyond the listed 32k context were not checked.
