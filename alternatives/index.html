Jev alternatives (TypeSafe AI): open-source models, local runtimes and hosted APIs, and what each replaces

What can replace Jev (TypeSafe AI): open-weight models, local runtimes, request adapters and hosted decision APIs from OpenAI, Microsoft and Cloudflare, by layer and licence. "Alternative" can mean five different things: a different request library, a local runtime, a different trained model, another provider's hosted API, or a different kind of model altogether. Pick the layer you need to replace first; a matching request shape does not mean matching answers. Why this title: Google completes "jev alt" to "jev alternatives"; Bing and DuckDuckGo complete it to "jev alternative" (autocomplete, 10 Oct 2026, 05:17 UTC; R12-S11). A suggestion shows that people search for it, not how many.

Jev weights: not found on TypeSafe's site, docs, GitHub or Hugging Face (10 Oct). Of 33 listed substitutes: 13 model weights, 11 local runtimes, 4 request adapters, 2 classifier/LLM approaches, 3 hosted APIs from other providers (OpenAI, Microsoft, Cloudflare).

Short answer

Official weights or a local runtime. TypeSafe-published Jev weights or a local Jev runtime: not found on typesafe.ai (no /models page, HTTP 404), the docs (llms.txt, the models page, the introduction), TypeSafe's GitHub organisation (12 repositories: SDKs, an interface adapter, skills, examples, n8n nodes and two forks) or a Hugging Face author search for TypeSafe accounts (0 models), checked 10 Oct 2026, 05:11–05:20 UTC. Documented TypeSafe's docs describe Jev as hosted: "the same weights serve every account". Its new Enterprise page lists the question "Can we run Jev in our own VPC or on-premises?", but the answer is not in the served page and the pool has not read it. (R12-S100–S110, R12-S21, R12-S36, R12-S58)

Can you run Jev in Ollama? Not TypeSafe's Jev on the evidence checked. Ollama's library search for "jev" showed no Jev-named model on its first page (10 Oct 2026, 05:11 UTC), and no TypeSafe weights were found (above). Ollama 0.35 (blog, 29 Sep) runs other Jev-style decision models (nimble from Bespoke Labs; tev1 and tev1:0.8b from Together AI) behind a System One-style endpoint. OllamaMQ v0.5.0 is a queue in front of such servers, not a model. Documented (R12-S107, R12-S135, R12-S136)

Other options. If you need local weights, the independently trained options with inspectable repositories and model cards are Kev, CLM, Laya and Jeff, among others; Kev and CLM also expose a System One-style API. Ollaya (new on 28 Sep) runs several of these models locally behind a System One-compatible API. The pool has run no parity test of its own (nothing run as of 10 Oct 2026); their accuracy figures are the authors' own. Published comparisons with Jev: Opper's Jev–Kev comparison (B11, grade B, operator with a stake). Three comparisons of Jev with OpenAI's Decisions API are graded and differ by task: see its row (B38, komzweb, and B39, mateusfonsek, since 11 Oct 2026; B41, kartikanand73, since 12 Oct 2026; all three grade A). One graded comparison includes Microsoft-Decision-1: On synthetic bank-withdrawal routing (B41, grade A), Jev (89.2% macro-F1) and Microsoft-Decision-1 (87.6%) were not separated and both were ahead of OpenAI's Decisions API (71.4%); Decision-1 kept the same route across all 6 option orders more often (97.2–97.6% vs Jev 91.6–91.8%, Decisions API 64.2%). Reported; see its row. Hosted Jev, Laya and Kev are compared on the same rows on Jev vs Laya vs Kev. (This paragraph: rows checked 26 Sep–1 Oct, not rechecked on 10 Oct.)

Another provider's hosted API. Another provider's hosted decision API is a different layer. The table lists 3. OpenAI's Decisions API (public beta) runs its own model, gpt-6-luna, behind a different request shape, and your data goes to OpenAI (row; R12-S134, R11-S300). Microsoft-Decision-1 (published 9 Oct 2026) is listed in Microsoft Foundry's catalog and on OpenRouter; it is text-only, and your data goes to Microsoft under Microsoft's terms (row; R14-S208, R14-S209, R14-S212, checked 12 Oct 2026, 05:13 UTC). Cloudflare's Clef family (Clef, Clef-flash, Clef-omni) runs on Workers AI with the same state-plus-questions shape as Jev but a different endpoint, and your data goes to Cloudflare under Cloudflare's terms on Workers AI; on OpenRouter's non-Cloudflare hosts (PrimeIntellect, DeepInfra) it goes to that host (row; R14-S400–S405, checked 12 Oct 2026, 05:33 UTC; R15-S226, 13 Oct 2026, 05:21 UTC); its weights are also published (row). All three are alternatives, not products built on Jev. See the hosted-API layer. Compare side by side: Decisions API vs Jev vs Microsoft Decision 1.

Choosing between Jev, a general LLM with JSON output and a trained classifier is a different question: see Jev vs an LLM vs a classifier: when to use which. Published accuracy tests, graded by how far they can be checked, are on the benchmarks ledger.

Which layer do you need to replace?

You needChooseDo not choose it if
Keep your request code, change the providerAn API interface adapterYou need data to stay local: adapters forward requests to another provider or model.
Run on your own hardwareA local runtime or independent weightsYou need Jev's calibration or accuracy: local runtimes wrap other models and were not compared on your task.
Open weights you can fine-tune or auditIndependent weights (Kev, CLM, Laya, Jeff…)You cannot check separate code, adapter and base-model licences, or you need more than the model's context (Laya about 512 tokens, CLM 2k by default).
A hosted decision API, but not JevAnother provider's hosted decision API (OpenAI Decisions API, public beta; Microsoft-Decision-1; Cloudflare Clef family)Your data must not go to that provider, or you need Jev's exact answers (a different model answers).
Free-text output, or you already have labelled dataAn LLM with structured output, or a trained classifier (10 criteria compared)You need per-option probabilities without training.
