Open-source alternatives to Jev (TypeSafe AI): what each one actually replaces

"Alternative" can mean four different things: a different request library, a local runtime, a different trained model, or a different kind of model altogether. Pick the layer you need to replace first; a matching request shape does not mean matching answers.

Short answer

TypeSafe's own Jev weights were not found published (checked 26 Sep 2026). If you need local weights, the independently trained options with inspectable repositories and model cards are Kev, CLM, Laya and Jeff, among others; Kev and CLM also expose a System One-style API. Ollaya (new on 28 Sep) runs several of these models locally behind a System One-compatible API. None has a same-workload parity test against Jev by this pool; their accuracy figures are the authors' own, and one operator (Opper) published a Jev–Kev comparison. Hosted Jev, Laya and Kev are compared on the same rows on Jev vs Laya vs Kev.

Choosing between Jev, a general LLM with JSON output and a trained classifier is a different question: see Jev vs an LLM vs a classifier: when to use which. Published accuracy tests, graded by how far they can be checked, are on the benchmarks ledger.

Which layer do you need to replace?

You needChooseDo not choose it if
Keep your request code, change the providerAn API interface adapterYou need data to stay local: adapters forward requests to another provider or model.
Run on your own hardwareA local runtime or independent weightsYou need Jev's calibration or accuracy: local runtimes wrap other models and were not compared on your task.
Open weights you can fine-tune or auditIndependent weights (Kev, CLM, Laya, Jeff…)You cannot check separate code, adapter and base-model licences, or you need more than the model's context (Laya about 512 tokens, CLM 2k by default).
Free-text output, or you already have labelled dataAn LLM with structured output, or a trained classifier (10 criteria compared)You need per-option probabilities without training.

Seen, not yet checked

These appeared during the 27–28 September scan. They are leads only: no licence, parity or safety claim is made beyond what each project states. Unverified

  • Jeva.cpp: a llama.cpp fork with a "JEV-compatible decision API" (repository states MIT).
  • Gevva0: a local decision gateway on Gemma (repository states Apache-2.0).
  • Rene-1 31B: claims "+9 over Jev" on a "Decision Index"; a benchmark claim only (the card marks its score verified: false; graded D, B18). The card says Apache-2.0; the base model is not stated in the card metadata (checked 30 Sep 2026).
  • Jeff (firelex): repository created 28 Sep, v1.1 on 29 Sep; code MIT, weights licence not checked. The README says "On benchmarks they approach, and sometimes beat, Jev" (graded D, B20). Not the same project as the Gestalt-Lab or logan-markewich Jeff rows above.
  • llama-system1: an npm shim exposing /v1/systemone for llama.cpp.
  • OllamaMQ v0.5.0: announced "SystemOne APIs" support (Hacker News post, not opened).
  • kev-onnx: a CPU-only ONNX server for Kev with a /v1/systemone API.
  • AnyJev v0.2.0 was released on 28 Sep. Whether it is the same project as the "JevAny" row above was not verified, so they are kept separate.

Two videos compare Laya and Kev without running Jev: Zahiruddin Tavargere's re-run on Laya only, and RUNTIME's "Kev vs Laya" (its description: "30 frozen synthetic cases … Kev matched our policy 26/30 times and Laya English 12/30"). These are author-run comparisons, not Jev demos, and are therefore not listed on the videos page. Reported The graded tests that ran Jev with Laya or Kev are collected on Jev vs Laya vs Kev.

Jev vs Kev: one operator-reported comparison

Opper's 25 September article, with benchmark code, a 362-item manifest and results, reports one run on 160 arXiv labels, 120 Stack Exchange sites and 82 GitHub issue labels. Reported It is row B11 (grade B; flags COI, small-n) on the benchmarks ledger.

Opper sells route access to Jev and hosts one of the compared models, so it is not a neutral party. This pool did not rerun the suite.

What was not verified

  • No same-workload, same-hardware parity test of any alternative against Jev.
  • Base-model licences and some checkpoint and adapter licences (JevAny adapters, vjev-vision) were not established.
  • "Local" is not a privacy guarantee: check downloads, network calls, logging and retention for each project.
  • Rows keep their own check dates (22 September–1 October). On 1 October only Kev and Laya were rechecked.
  • Ollaya's per-model licences, the origin of its benchmark and Kev-9B's base licence were not checked. Laya's and Kev's System One compatibility is stated by their authors, not tested by the pool.
