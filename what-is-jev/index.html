What is Jev (TypeSafe AI)? A plain explanation of Choice, Score and Noul

Jev is a hosted model from TypeSafe AI. Your application sends it some text or structured data (the state) and one or more typed questions. For each question Jev returns an answer from a fixed set, with probabilities. It does not write prose or code.

Short answer

Jev is a decision model, not a chatbot. You ask "which of these options?", "where on this 2–10 level scale?" or "yes or no?", and it returns the answer and its probabilities. Your code then checks the answer and decides whether to act, send the case to a person, or fall back to another method. Documented TypeSafe API and primitives docs, checked 28 Sep 2026

Name check: this page is about TypeSafe AI's Jev model. It is not about Japanese encephalitis virus (JEV) or any person named Jev.

One request, step by step

The request and response, annotated

Documented Request adapted from TypeSafe's quickstart (model pinned, one question kept). Not executed by the pool.

curl -X POST https://api.typesafe.ai/v1/systemone \
  -H "Authorization: Bearer $TYPESAFE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "state": "Help! My payouts have been failing for 3 days.",
    "model": "jev-1.13.0",
    "questions": {
      "department": {"type": "choice", "instructions": "Which team should handle this?",
                     "criteria": {"billing": "Payments, invoicing, refunds",
                                  "technical": "Bugs, outages, integrations",
                                  "sales": "Pricing, upgrades, new accounts"}}
    }
  }'

Documented Response fields and values from the API reference's example for a department Choice. The two examples come from different documentation pages, so this response is not the output for the request above.

{
  "model": "jev-1.13.0",
  "answers": {
    "department": {
      "type": "choice",
      "choice": "billing",
      "probabilities": {"billing": 0.88, "technical": 0.12, "sales": 0.0},
      "confidence": 0.81
    }
  },
  "usage": {"input_tokens": 318, "output_tokens": 34}
}
  • model is the versioned model that answered, even if you sent an alias such as jev-latest.
  • choice is the highest-probability option; probabilities sum to 1.
  • confidence (0.81) measures how peaked the probabilities are. It is not the chance that "billing" is right.
  • usage.input_tokens (318) is what TypeSafe bills; output tokens are reported but free on the direct route. See cost per decision.

Checked 28 Sep 2026. Full, version-pinned Python code is on Call Jev from Python.

The three question types

TypeYou provideJev returnsUse it forWatch out for
ChoiceUp to 255 named optionsThe chosen option, a probability for each option, and a confidence numberRouting to a queue, picking a label, picking a UI element or toolChoice always picks something. Add an explicit "other" or "review" option when the list may be incomplete.
ScoreAn ordered rubric: at least 2 levels recommended, at most 10 acceptedA probability-weighted position on that scale, probabilities per level, and a confidence numberUrgency, severity, toxicity, quality gradesThe number is a position on your rubric, not a calibrated percentage.
NoulA yes/no questionThe probability of yesGates: "is this spam?", "does this quote support the claim?"There is no third "unsure" outcome and no separate confidence field; you choose the cut-offs.

Documented Option and level limits from TypeSafe primitives and the API reference, checked 28 Sep 2026. confidence measures how peaked the probabilities are; it is not the probability that the answer is correct. Details are on Confidence thresholds.

Worked example: a support ticket

A customer writes "I was charged twice this month and can't log in to see the invoice." Your application could ask two questions in one request:

QuestionType and answer setWhat your code does with the answer
Which queue?Choice: billing, bug, account, reviewRoutes to the chosen queue only if its probability is above the cut-off you tested; otherwise sends it to "review".
How urgent?Score: 1 (low) to 4 (outage)Sets a priority field. Refunds and account changes are never triggered by the answer alone.

This ticket mentions two problems (billing and login). A good design lets it land in "review" or in both queues, rather than forcing one label. This example restates the support-routing pattern in TypeSafe's and Netlify's documentation; it is not a result of a call made by this pool. What five real ticket-triage projects do when Jev is unsure or fails is on support-ticket triage.

What Jev does not do

Jev returns probabilities over options you define; it does not generate text, take images or audio, do arithmetic or date comparison reliably, or guarantee that a valid answer is correct. TypeSafe's model jaggedness page (last reviewed 17 Sep 2026) lists the weak task types with workarounds; all 17 documented limits are on Limitations and fit check. Documented checked 28 Sep 2026

What was not verified

  • This pool has not made a Jev call; the example above is a design, not an output.
  • Accuracy on any task is not established here. See Confidence thresholds for how to test on your own data.
  • Independent open-weight Jev-like models (Kev, CLM, Laya and others) are not TypeSafe's weights and have no verified parity; see Alternatives.
