Access, price and limits on 9 October

Unchanged, as observed 9 Oct 2026, 05:16–05:17 UTC source link not kept

  • Signups had been open since 27 Sep, 22:33 UTC, and new accounts got no free credit.
  • The API was operational, with no status-page event since 29 Sep.
  • Price ($0.042 per million input tokens), limits (100K tokens per second, 80 requests per second), model (jev-1.13.0), aliases (jev-latest and jev-preview both pointed to jev-1.13.0) and all six route IDs were unchanged. The access status page shows the same values from its 8 and 10 Oct checks.
  • Official sites and resellers: all 5 sites returned HTTP 200 at 05:17 UTC.

The site's versions and aliases page records 32,000 on 8 Oct and, from 10 Oct, 64,000 with a 32,000-token prompt limit; no other page states the 57,600 figure.

Rerankers and context filters: what reaches the prompt when Jev fails

Five implementations were read in source at the versions below. On a Jev error, 3 of the 5 still put text Jev never judged into the prompt (Spring AI by failing open, LlamaIndex and LiteLLM by falling back), and 2 raise an error instead. The current reranking and RAG page describes the same five error cells as 2 stop, 2 fall back and 1 passes unscreened passages.

Studies of Jev as a reranker

iwhalen (grade A) measures agreement with human relevance grades and system ranking, not reranked retrieval. The reranking-pipeline studies by jev-reranker and LanceDB (both grade B) come from parties that ship a Jev reranker; the LanceDB benchmark script uses the shipped class and a no-reranker baseline. The code of these three studies was not read.

One study from a party that ships no Jev reranker, zhuyansen/jev-search-rerank-eval (c896f14, 164 queries), reports +0.012 nDCG@10 [−0.013, +0.037] when Jev reranks bge-m3's top 30 Reported source link not kept. Only its README was read, not its evaluation code. It is not on the site's benchmarks page, which names jev-pulse (B37) and jev-rerank-bench (B40) as the graded studies whose authors state no stake.

Open questions about these implementations

The 9 Oct readings left these questions open. Where a later dated report on this site covers the same question, it is linked; the site does not settle every point.

  1. When Jev errors, does the Hermes jev-approvals plugin stop and ask a person, or can a fallback model approve the command? Hermes core call_llm at v2026.9.24 (f97608f, agent/auxiliary_client.py lines 7610–7634 and 7749) first retries, then falls back to other configured LLM providers on connection, timeout, exhausted-429, quota and malformed-response errors, even for an explicitly chosen provider, before it re-raises. A fallback model could answer APPROVE, and core runs an APPROVE without a person. Not read: whether the plugin's own provider errors take that path, or how the plugin's provider is registered in Hermes. Later reports: the 8 Oct report records a fallback to the main agent model; the 11 Oct report adds "with no main model configured, it asks you". The site does not say whether the plugin's own provider errors take the path described here.
  2. With no Jev key, does openlayer jevals fail closed or fall back to another backend? With no backend and no credential it raises BackendError (backends/__init__.py lines 52–55); with another credential set, it uses that backend, which can be an OpenAI or OpenRouter LLM judge. The 9 Oct count classed it as fail-closed; counted as a fallback, its no-key row would read fail-closed 34, fallback 10. Later report: the 8 Oct report counts it as a fallback to another backend, and fail-closed when no other backend is configured.
  3. Does pg-redact store text unredacted, or show a span unmasked? As read on 9 Oct, pg-redact always stores the raw message body and masks at display time from the stored spans, so "shown unmasked" describes the code more closely than "stored unredacted"; the 7 Oct report line ("that text is not redacted") remains accurate on that reading. No later report on the site takes this up. The current SQL and document pipelines page says it "stores text unredacted".
  4. Which rh-guard line supports its low-confidence behaviour? The 9 Oct reading points to Jev confidence below 0.5 in score.ts (lines 110–116) and treats the 0.45 in kinds.ts (line 36) as a different measure, a risk-score review cut. Later report: the 8 Oct report draws the same distinction. The site links score.ts lines 98–127, not 110–116.
  5. What does jev-curator do on a malformed answer, below the threshold and with no key? Read on 9 Oct as fail-closed, held and fail-closed. Later report: the 8 Oct report fills the same three cells.
