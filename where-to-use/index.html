Where to use Jev (TypeSafe AI) and what it costs: routes compared

You can call Jev directly from TypeSafe or through five gateways. The listed input price is the same or nearly the same on every route that shows one; the routes differ in request shape, context limit, data terms, billing and who you have an account with.

Access today: Available to new users: signups open, but new accounts get no free credit. API operational. Signups open since 27 Sep 2026, 22:33 UTC (TypeSafe CEO's post). Status checked 7 Oct 2026, 05:19 UTC; the pool did not sign up itself. Documented Access status, how it was checked, and timeline
Short answer

TypeSafe lists jev-1.13.0 at $0.042 per million input tokens, output free. OpenRouter, Cloudflare and Vercel (in its models API) list the same price; Vercel's web page and Opper's card round it to $0.04; Netlify bills in its own credits at an unknown rate (checked 7 Oct 2026, 05:19 UTC; Netlify 28 Sep). TypeSafe's published rate limits are now 100K tokens per second and 80 requests per second; the request limit was 40 per second until at least 2 Oct, 05:14 UTC (changed by 3 Oct, 05:16 UTC). Use TypeSafe direct or Opper if you need the 64k request budget; use OpenRouter if you do not want a TypeSafe account. If you need zero data retention, it must hold at both the gateway and the provider: OpenRouter and Cloudflare label the TypeSafe provider zero-retention, and on Vercel you must enforce it (data handling by route). None of these listings proves an account can call Jev or what it will be billed. Jev is not listed in the Amazon Bedrock model cards or the Azure AI Foundry model catalog at 5 Oct 2026, 05:18–05:19 UTC (the checks).

Before you pay anyone. Unofficial resellers charge 3–16× the list price; check any other site on official vs reseller sites. To estimate a monthly bill from your own token counts, use the cost per decision worksheet.

Choosing on context and data terms

  • 64k request budget: listed by TypeSafe direct and Opper, and in the text of Vercel's API description (whose context_window field says 32000). OpenRouter, Cloudflare and Netlify list 32k.
  • Zero data retention: it must hold at both layers. For the TypeSafe provider, OpenRouter (ZDR list) and Cloudflare ("Yes") label it zero-retention and Vercel's docs mark it ✓, but Vercel also routes to DigitalOcean, which it marks as not ZDR. Opper says "not established". TypeSafe offers ZDR directly "for enterprise customers". Quotes and a checklist: data handling by route.
  • No TypeSafe account: every gateway; OpenRouter states it explicitly.
  • Exact cost per response: OpenRouter returns usage.cost with each response.

Is Jev on Amazon Bedrock or Azure AI Foundry?

Short answer

Jev is not listed in the Amazon Bedrock model catalog or the Azure AI Foundry model catalog (checked 5 Oct 2026, 05:18–05:19 UTC), and TypeSafe's docs do not mention either. Call TypeSafe's API or a gateway.

Documented Not listed in the Amazon Bedrock model cards (19 providers) at 5 Oct 2026, 05:18 UTC. Not listed in the Azure AI Foundry model catalog (search "typesafe" and "jev": 0 models) at 5 Oct 2026, 05:19 UTC. "Not listed" is what the public pages showed; private offers and signed-in listings were not checked.

Boundaries: AWS Marketplace and Azure Marketplace results were read on the first page only. Private offers, listings visible only when signed in, regional catalogs and enterprise contracts were not checked. This does not mean Jev will never be on either platform.

How to reach Jev from AWS or Azure today

These are the routes already in the route matrix; nothing here is new about them.

  1. TypeSafe API directly (api.typesafe.ai/v1/systemone, key from the console). Prompts leave your VPC or tenant over the public internet to TypeSafe, which processes them on US compute (trust center). No PrivateLink or VNet option was found in TypeSafe's docs (boundary: llms-full.txt, 5 Oct 2026, 05:17 UTC).
  2. OpenRouter (typesafe/jev-1.13; no TypeSafe account needed). Data goes to OpenRouter, then TypeSafe. The endpoint is on OpenRouter's ZDR list.
  3. Vercel AI Gateway, Cloudflare, Opper or Netlify. Each adds a gateway hop before the provider. Opper is an EU-based gateway, but its TypeSafe route is listed as "United States".
  4. From a Foundry agent: an OpenAPI tool that points at TypeSafe's API (the Microsoft Tech Community post below does this). The decision runs at TypeSafe, not in Azure.

What leaves the cloud

  1. Your code on AWS or AzureLambda, AgentCore, a container, a Foundry agent
  2. Public HTTPSoutside the Bedrock or Foundry model boundary
  3. Gatewayoptional: OpenRouter, Vercel, Cloudflare, Opper, Netlify
  4. TypeSafeUS compute: AWS, Modal, Nebius or CoreWeave (trust center)

Whichever route you use, the data path leaves AWS Bedrock's or Azure's model boundary, so Bedrock Guardrails and Foundry content filters do not see the Jev call. Retention, training and ZDR per route: data handling by route.

What others say

  • Reported FactualMinds, a consultancy, in "Jev (TypeSafe AI) on AWS with Bedrock (2026)" (about 20 Sep): "Jev is not an Amazon Bedrock model. There is no inference profile, no VPC endpoint, and no Guardrails hop." It describes Jev as a sidecar called from Lambda or AgentCore over public egress to api.typesafe.ai.
  • Reported Microsoft Tech Community, "Using Jev with Agents in Microsoft Foundry for Model Evaluation" (community blog, about 26 Sep): it builds a Foundry agent with an OpenAPI tool whose operation calls POST https://api.typesafe.ai/v1/systemone with a TypeSafe key. Jev is not a Foundry catalog model there.
  • A lookalike reseller site, jevtypesafeai.com, has a "Jev on AWS Bedrock" page. It is not a source for this section; see official vs reseller sites.

Before you send real data

  1. Pin jev-1.13.0 instead of an alias if your thresholds depend on one model version (on Vercel and Cloudflare you cannot; see what to pin on each route). Recheck aliases and limits before a pilot.
  2. Use synthetic or redacted inputs until you have checked the account's access, retention, credits and terms. A public listing is not a successful call.
  3. Read the TypeSafe MCA, privacy policy and DPA for your workload. On 7 Oct 2026 (05:19 UTC) the MCA still showed "last updated 23 Sep" (what changed from 19 Sep is unknown), the privacy policy 19 Nov 2025 and the DPA 24 Apr 2026. The training, retention and ZDR clauses are quoted on data handling by route (a reading of the text, not legal advice). Until its 19 Sep version the MCA also barred publishing benchmarks; see the terms box on the benchmarks page.
  4. Handle the documented 401, 422, 429 and 529 responses with a fallback in your own code; see errors and rate limits.
  5. Do not copy a context limit from one route to another: TypeSafe's 64k budget is not established for gateways that list 32k.
