What changed with Jev 1.14

TypeSafe published the post "Jev: For the builders AND dreamers" (dated 14 Oct 2026) and updated its models page. What the pages say, checked 16 Oct 2026, 05:21–05:26 UTC:

  • Aliases. jev-preview → jev-1.14.0; jev-latest → jev-1.13.0 ("The most recent stable, official release. The default in our client SDKs"). TypeSafe's 14 Oct post said: "jev-latest will be updated to jev-1.14.0 in a week. jev-1.13.0 will be available for a while." It also said it intends "60 days warning before jev-1.13.0 is formally deprecated, and 30 days for jev-1.14.0", and that a deprecation policy will be published first. Documented (models page, R17-S05; TypeSafe blog, R17-S09) The move was first seen on 24 Oct 2026, 05:12 UTC: jev-latest → jev-1.14.0 and jev-preview → jev-1.14.0 (it had not happened at 23 Oct 2026, 05:45 UTC). TypeSafe has published no 1.13 deprecation date, and no deprecation policy page was found on its blog index or models page (24 Oct 2026, 05:12 UTC; R23-S05, R23-S08, R23-S09). If you tuned thresholds on 1.13, send jev-1.13.0; this restates TypeSafe's own advice to "send that version's ID instead of the alias".
  • Price. jev-1.14.0 and jev-1.13.0: $0.042 per million input tokens ($42 per billion); output free; long context costs the same per token. Unchanged for 1.13 since 28 Sep. Documented (R17-S05)
  • Images (experimental). Text is the default input on both versions. Images are accepted only with the opt-in header TypeSafe-Danger-Zone-Images: true, on both versions. TypeSafe says images and Box "aren't yet up to our standards to call ready for production": experimental, not production-ready per TypeSafe. No audio or video. The post says jev-1.13.0 "was multimodal all along" Reported. (R17-S05, R17-S06, R17-S09)
  • Box questions (experimental, 1.14 only). A bounding-box question type. On 16 Oct 2026 TypeSafe's Box page said: "Box questions need Jev 1.14: send jev-preview or jev-1.14.0" (R17-S20). On 24 Oct 2026: "Box questions need Jev 1.14" (images page); on TypeSafe's API jev-latest, jev-preview and jev-1.14.0 all give 1.14 since 24 Oct; TypeSafe's own image and Box examples send jev-latest (images.md L29, L169, L215; box.md L33; R23-S06, R23-S19). Not production-ready per TypeSafe. Documented
  • Long context (experimental). Default limits on both versions: 64k tokens per request and 32k per question. The opt-in header TypeSafe-Danger-Zone-Long-Context: true raises both to 262k tokens on 1.14 and 1.13. TypeSafe says long context is "slower and less accurate" Reported. (R17-S05)
  • Rate limits. Until at least 14 Oct 2026, 16:46 UTC the models page listed 100K tokens per second and 80 requests per second (R16-S05). On 16 Oct 2026, 05:21 UTC it lists no numbers: "Rate limits are set per organization. Your organization's current limits are in the developer console." The pool has no account, so it cannot see the current numbers. Documented (R17-S05; see errors and rate limits)
  • Quality. TypeSafe says 1.14 brings "small, subtle improvements to everything", with "the largest gain in multi-lingual support". Reported Not tested here.

Documented vs experimental: text questions on both versions are TypeSafe's standard offering. Images (both versions), the Box question type (1.14 only) and 262k long context (both) are opt-in "Danger Zone" features that TypeSafe says are not yet production-ready (R17-S05, R17-S06, R17-S20). No image, Box or long-context request was sent.
