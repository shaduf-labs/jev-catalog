Jev 1.13 and jev-latest (TypeSafe AI): model IDs and aliases by route

When the pool checked search suggestions on 6 Oct 2026, 05:19 UTC, Google, Bing and DuckDuckGo all offered "jev 1.13" and "jev-latest". "jev 1.14", "jev versions" and "jev model version" had no supporting suggestion. A suggestion shows that people search for a phrase, not how many do. This page lists, for each of six routes, the Jev model IDs you can write, the aliases and what they point to, and whether you can pin a version.

Key finding

On 4 of 6 routes read on 6 Oct 2026 you can write a versioned Jev ID; Vercel and Cloudflare take only an unversioned one. jev-latest points to jev-1.13.0 on TypeSafe's models page.

Documentedroute pages and model APIs, checked 6 Oct 2026, 05:15–05:24 UTC; rechecked 10 Oct 2026, 05:12 UTC, unchanged

Picked from the six routes on the route matrix that serve TypeSafe's Jev; not a survey. The pool read public pages and model APIs only: it sent no request to any route and made no Jev call, so what each route actually serves is not tested. The 4 routes with a versioned ID are TypeSafe direct, Netlify and Opper (patch level, 1.13.0) and OpenRouter (minor version only, 1.13).

What TypeSafe says about its aliases

  • Alias rule: "An alias moves when a new release ships, so the answers behind it can change without a change on your side. … pin that version's ID instead of the alias." (models page, read 6 Oct 2026, 05:15 UTC)
  • Preview: "jev-preview currently points to the same model as jev-latest. There is no preview build available right now."
  • Response: The response's model field "reports the versioned ID that answered" (TypeSafe direct).
  • History: The models page lists one version, jev-1.13.0, with no "previous versions" or deprecation text. TypeSafe's docs changelog.md returned HTTP 404 (05:15:35 UTC). The pool has not seen a Jev version change: there has been one version so far.

Documented TypeSafe's GET /v1/models list, which the docs say carries the aliases and a release_date per name, needs a key and was not read.

What to pin

  1. Where a versioned ID is accepted, write it. jev-1.13.0 on TypeSafe direct and Netlify; typesafe/jev-1.13.0 on Opper; typesafe/jev-1.13 on OpenRouter (minor version only). TypeSafe's own wording: "If you have tuned confidence thresholds against a specific version, pin that version's ID instead of the alias." See confidence thresholds.
  2. On Vercel and Cloudflare you cannot pin. Neither source states which Jev version the unversioned ID serves. On Cloudflare, the documented example response includes a model field ("jev-1.13.0"); if your responses carry it, log it. Whether every Cloudflare response carries it, and whether Vercel's responses report a versioned ID, was not checked.
  3. On TypeSafe direct, log the response's model field even when you pin: TypeSafe says it reports the versioned ID that answered.
  4. If you use an alias, today jev-latest and jev-preview point to the same model on TypeSafe's models page and in Opper's catalogue. Netlify lists both without stating targets. Recheck the models page before you rely on an alias target.

Documented Advice built from the route sources above; no route was called.

Which model the SDKs send by default

TypeSafe's models page says jev-latest is "The default in our client SDKs" (read 6 Oct 2026, 05:15 UTC). Documented The default of each SDK and framework package was not checked package by package on 6 Oct 2026 (the planned search of @ai-sdk/typesafe-ai, the LangChain packages, Pydantic AI, @effect/ai-typesafe, typesafe-spring-ai and the n8n node was not done). The defaults recorded in earlier source reads are on TypeScript SDK, Python SDK and framework integrations.

What was not verified

  • What each route actually serves: no request was sent to any route, and no agent, SDK or Jev call was run.
  • Whether OpenRouter accepts a patch-level ID (typesafe/jev-1.13.0) or the dated build name (jev-1.13-20260917) as a model ID.
  • Whether Vercel or Cloudflare would move their unversioned IDs to a new version, and how they would announce it. No version change has happened yet.
  • Route changelogs: only TypeSafe's was checked, and it returned 404. No OpenRouter, Vercel, Cloudflare or Opper changelog was read; Netlify's TypeSafe changelog post was not reread.
  • SDK default models beyond TypeSafe's statement.
  • TypeSafe's keyed GET /v1/models list.
