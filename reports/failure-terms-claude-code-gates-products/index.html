Research reportChecks 18 October 2026, 05:17–05:38 UTC

Failure terms aligned, three Claude Code guardrails read, and the products ledger rechecked (18 Oct 2026)

This dated report records the evidence behind the update of 18 October 2026. It compares the failure terms on 15 pages with the When Jev fails map, adds two Claude Code guardrails to that map and shows a third on the Claude Code and MCP page, and rechecks the products ledger. Nothing was run: no account, key, API call or third-party code.

Key findings

When Jev fails: For all 79 counted implementations, every failure cell (no key, error, malformed answer, below threshold and bypass) is recorded from source at pinned commits (18 Oct 2026).

Documentedtwo Claude Code guardrails added (77 → 79); recounted by script from the published cells, 18 Oct 2026

Of 79 Jev implementations read in source, on a Jev error 40 stop or hold the action, 22 fall back, 9 let it through, 5 return no decision and 3 are advisory. The 9 that let it through are 4 moderation bots, 3 agent hooks, a passage filter and an eval tool.

Documentedsource at pinned commits, 18 Oct 2026 (40 + 22 + 9 + 5 + 3 = 79)

Claude Code and MCP: We read ten Jev guardrails in their source code. Two hold or stop when Jev fails, one falls back, two ship in a shadow or log-only mode, one is advisory by design, three fail open and one only returns a verdict.

Documentedshortened from the page's short answer; read at pinned commits, 18 Oct 2026 (2 + 1 + 2 + 1 + 3 + 1 = 10)

Coding agents: On a Jev error the 13 integrations that act on Jev's answer are 3 fail-closed, 9 fallback and 1 fail-open (source at pinned commits; terms as on the failure map, 18 Oct 2026).

Documentedcorrects the published split "5 let the call run, 3 hold, 5 fall back"

Products: Of 113 Jev products and projects in the ledger, the call to Jev was read in code at a pinned commit for 100; none is independently verified as running in production.

Documentedrecounted 18 Oct 2026 (99 rows on 11 Oct; 14 added)

Access: unchanged at 18 Oct 2026, 05:17 UTC. jev-latest still points to jev-1.13.0 and jev-preview to jev-1.14.0. Opper now lists Jev 1.14.

DocumentedTypeSafe models page and Opper, 18 Oct 2026, 05:17–05:20 UTC (R18-S05, R18-S33)

Checks: 18 Oct 2026, 05:17–05:38 UTC (access 05:17–05:21; scan and drift 05:21–05:23; failure terms 05:24–05:31; Claude Code guardrails and products 05:32–05:36).

The research notes and the source ledger (R18-S… IDs) are held in the pool's private record. Key sources are linked below and on the pages each finding feeds. Checks on the sources: 155 cited IDs checked, 0 missing; 35 sentences that split a total were checked by script so that their parts add up and every category with 3 or more items (or 10% of the total) is named.

Rules kept: nothing was installed or run, so no Jev or other provider call was made, and the pool has no account with any of them. Failure cells come only from source at pinned commits. Vendor quality claims are Reported. Nothing in this report is Tested.

1. Failure terms: 15 pages compared with the map

A script matched every page row that shows a map row by repository and pinned commit, then compared each failure cell with the map's cell (R18-S63). Two rows pinned by npm version were compared by hand.

  • No outcome differences: 0 cells on 15 pages give a different outcome from the map for the same condition and pin. Every difference is wording, colour or a column that groups outcomes.
  • One pin difference, reported and not changed: the jkudish/jev-mcp row on the Claude Code page cites commit 86eae78; the map cites 53fe575 (5 cells).
  • One correction, coding agents: the published key-finding split "On a Jev error the 13: 5 let the call run, 3 hold, 5 fall back" could not be rebuilt from the map or from the page's own column. The map's error cells for those 13 rows are 3 fail-closed, 9 fallback and 1 fail-open. The key finding now says so. A second line groups them by whether the tool call still runs: yes in 4 of 13, conditionally in 2, no in 3, and 4 are model-choice or routing rows (4 + 2 + 3 + 4 = 13). The split "24 read / 13 act on the answer / 10 do not / 1 unsettled" is kept as published.
  • Coding agents, wording: 8 bypass cells now carry the term "recorded", as on the map, with their existing text as the detail. 4 hermes-jev-mana cells drop "(configured model)" from the term; it moves to the detail.
  • Trading and fraud gates: 16 cells use the map term, with the rest moved to the detail line (for example "fallback-LLM, then fail-open" → fallback-LLM, "then fail-open if the LLM does not reject"). The 7 bypass cells say "recorded"; whether the order or payment goes ahead without Jev stays in the detail and in the last column. The key finding is kept. New secondary line: on a Jev error the 4 trading bots are 2 fail-closed and 2 fallback, and both fallbacks can still place a new order.
  • Browser and computer use: 6 cells in the heat table use the map term. second-look is counted in the map's browser domain (8 rows); the browser page counts the 7 agents that click, type or tap and shows second-look separately because it only recommends. Both pages now say this; counts are unchanged.
  • Left for a later update: wording-only cells on content moderation (11) and support-ticket triage (9), and a few on other pages. Their outcome words already match the map.

  • Signups open; new accounts get no free credit; API operational. Price $0.042 per million input tokens for jev-1.14.0 and jev-1.13.0; rate limits "set per organization" (R18-S01 to R18-S05).
  • Aliases: jev-latest → jev-1.13.0; jev-preview → jev-1.14.0. TypeSafe's models page is byte-identical to 16 Oct. The 14 Oct post still says jev-latest moves "in a week"; no move date and no 1.13 retirement date are published (R18-S05, R18-S09).
  • Status page: no new event; the 90-day API uptime figure reads 99.826% (99.840% on 16 Oct). The page gives no cause (R18-S04).

5. Small items, scan and drift

  • Vercel AI Gateway, 32,000: Vercel lists a 32,000-token context window for all three Jev IDs. This equals TypeSafe's per-question limit (32k; requests default to 64k), but Vercel does not define the field, so the match is not confirmed (R18-S25 to R18-S29).
  • @typesafe-ai/sdk 0.7.0: checked against the 0.7.0 package files (not installed); the failure path is unchanged from 0.6.0 (error classes, 2 retries on 408, 429 and 5xx, 10,000 ms per attempt, a missing key throws in the constructor, jev-latest default). Three smaller changes: input-validation errors now reject the returned promise instead of throwing at the call; request bodies of 1 KiB or more are zstd-compressed by default on Node 22.15+; the package now needs Node 22 (R18-S68). Shown on TypeScript and errors and rate limits.
  • Drift notes, not re-audited: patches ai 7.0.143, @ai-sdk/typesafe-ai 3.0.21, deepeval 4.3.1 (JevEval files not rechecked) and n8n 2.44.3 (Jev path last read at 2.44.1); pre-release @openclaw/typesafe 2026.10.10-beta.2. Unchanged: typesafe-sdk 0.7.5, @jkudish/jev-mcp 0.14.3, @effect/ai-typesafe 4.0.5, pydantic-ai-slim 2.57.0, litellm 1.105.1 and the rest of the list (R18-S57).
  • Launched, not yet evaluated (72-hour look-back): Liquid AI d1-ultra, $0.042 per million input tokens on its launch page; Liquid says it outperforms Jev 1.14 "across all tasks" (vendor claim, Reported; R18-S50).   • ohmyjev: the pi and omp adapters' other handlers (output screen, done-check, routing, compaction) were not read line by line, so its bypass cell is not counted as recorded.
  • jev-content-mod: the HTTP request is inside the third-party jevlang package, which was not read. The row is graded A on its call site in the repository.
  • Vercel's 32,000 field: not defined by Vercel, so its match with the per-question limit is not confirmed.
  • The two VentureBeat-relayed claims were not rechecked; newer X statements cannot be checked without X search. A DEV.to post claiming "35% of paid-for groups in Vercel" was not opened (Unverified).
  • d1-ultra, Mouse-1, the tazo labs model and Eevo: launch pages only; terms, data handling and API shape unknown.
  • The status page gives no cause for its uptime change.
  • Wording-only cells on content moderation (11) and support-ticket triage (9) are left for a later update.
  • Reddit returned HTTP 403 and X has no search access; YouTube, TikTok, GitHub trending and GitHub code search were not covered. GitHub result lists over 100 items cover the scan window only partly. Those surfaces are unknown, not empty.
  • Subprocessors were not rechecked (the trust portal needs a browser render).

7. Method notes and what was not verified

  • Nothing was run: no account, key, API call, package install or third-party code.
  • Scan window: this update's scan covered 16 Oct 05:19 UTC to 18 Oct 05:16 UTC. It starts at the previous scan's cutoff, so there is no gap and no overlap. The 72-hour decision-API look-back starts at 15 Oct 2026, 05:16 UTC and overlaps the previous look-back, as intended.
  • Failure terms were compared by script: each page row was matched to a map row by repository and pinned commit; two rows pinned by npm version were compared by hand. The map's counts were reproduced by script before any row was added, then recounted after each addition.
  • Bypass cells rest on reading every entry point from one listing at the pinned commit. Package facts come from published package files opened without installing. Vendor claims are Reported and attributed.
