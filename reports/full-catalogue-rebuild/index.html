Method: official documentation and providers for mutable API/access facts; repository README plus implementation/documentation for projects; first-party model cards/repositories for alternatives. Executive findings

1. The catalogue's two bounded negatives require revision. The six-item alternatives audit was accurate as a *22 Sep bounded search*, but today there are directly inspectable open-weight Jev-like models. TypeSafe's Jev weights were not publicly located or published in sources checked 25 September 2026; a compatible API does not make another model Jev. The old products audit was likewise a 23 Sep bounded search, not an ecosystem census. Direct Jev wiring exists in many more open projects than its four rows show, but this run still did not verify a working production customer/product deployment. Expand the project/demo section and retain the production-status bar.

2. A genuinely new, within-window project lead: Parcha AgentRun was posted in Show HN about 22 hours before the 25 Sep check. Its first-party repository documents an installable Jev adapter and an optional live-key path. The support demo is explicitly scripted and needs no key; label it *newly announced integration/SDK with scripted demo, live operation unverified*, not a live Jev product.

3. New research within the window, not product proof: Jev-Mobile was submitted 24 Sep 17:30:32 UTC; it reports Jev selecting mobile GUI actions from accessibility-tree state under VLM plans. This is an author-reported experiment; no independent replication or product deployment was checked. Jev in the Wild, submitted 24 Sep 17:46:08 UTC, studies 2,170 GitHub projects collected by 22 Sep. Its count is a paper's dataset claim, not 2,170 independently verified products.

4. Current official route: TypeSafe models still lists jev-1.13.0, aliases jev-latest and jev-preview both pointing to it, $0.042 per million direct input tokens and free output, 250,000 tokens/s and 1,200 requests/minute, 64k whole request and 32k state plus longest question. Limits are explicitly dynamic. The API is POST https://api.typesafe.ai/v1/systemone with Bearer key, model, state, and typed questions. No direct-account eligibility, live quota or credits were verified.

5. Access has expanded: add Netlify AI Gateway's official Jev route dated 17 Sep. It says Netlify Functions can use the TypeSafe SDK without separately configured API keys, billed in Netlify credits; its example is a vendor example, not a deployed customer. Vercel's model listing and launch changelog conflict on a current free/promo versus ~$0.04/M position on 25 Sep, so do not state a settled current charge without an account check.

6. X monitoring is inadequate. Public search yielded stale/irrelevant hits and no usable dated Jev post/feed for the window. The separate tools/access proposal is warranted. X's own pay-per-use page currently lists $0.005 per returned post, prepaid credits, no subscription/minimum commitment, and spending limits; the console controls current rates. A 100-post/day cap would be about $15/month in post-read charges, plus any other resource reads, but this is a planning estimate, not an account quote.

6. X tools/access proposal evidence for Manager

Recommended simplest workable option: official X API v2 recent search with a strict spend cap, if owner is willing to fund low-volume reads. X pricing says prepaid credits, no subscription/minimum, $0.005 per Post returned, $0.010/User read, $0.005/List read, daily UTC deduplication (soft guarantee), and developer-console spend limits; current rates controlled in console. X API overview describes v2 app credentials and search; pagination documents search_recent, created_at, author_id and pagination. Proposed data flow: owner creates X developer app at console.x.com, adds prepaid credit and a low monthly spending limit, supplies read-only Bearer token through secret storage, never in repo. A small scheduled script in the pool's runner environment queries recent posts at least daily (preferably every 6h to avoid missing deletions/rate gaps), saves id, URL, created_at, author, text, query, fetch time, pagination cursor and API errors as JSONL in a private dated evidence file, deduplicates IDs, then Runner follows each lead to a creator/repo/product primary source. Query terms: "jev" "typesafe", "jev-latest", "systemone" "typesafe", "@typesafeai", "jev" (github.com OR demo OR launched OR built), plus selected author accounts/lists from verified projects (TypeSafe, browser-use, Vercel Labs, Kev/CLM maintainers) after confirming handles. Search both global and known-account posts; exclude unrelated gaming “Jev” with TypeSafe/model terms. A cap of 100 new Post reads/day is ~3,000/month × $0.005 = $15/month; 20/day ~$3/month. These exclude user/list reads, taxes and any provider rate change. Start with 20–50/day and stop at budget; no purchase was made. This is a proposal, not current access.

Free fallback: owner manually exports/pastes links or a daily search digest into the pool, with post URL/time/author; Runner checks those and continues public-web search. This has low/irregular coverage and cannot establish a complete 24h feed. A self-hosted Nitter RSS/search setup is not recommended as the default: it relies on unofficial APIs and accounts, rate limits are documented in maintainer issue #1293, and its README notes 2026 takedown demands. It might cost no API fee but carries setup, account, reliability and legal/platform risk. Do not scrape public Nitter instances; its maintainer explicitly objects. Public web search is a supplementary lead source, not adequate X monitoring.

Unresolved items and next checks

• No independently verified production Jev deployment in this audit. Direct code and installable packages are real, but named customers, active workloads, current live operation, and user adoption were not substantiated. Ask maintainers for a public deployment/case study or reproducible live evidence before upgrading.

• Source access: GitHub native created/pushed search cache misses, X inaccessible as current feed, TikTok robots denial, YouTube native recent list cache miss, Reddit native new/day cache miss, DEV Go SDK repo cache miss. The platform log records negative findings as not verified, not complete absence.

• Model competition: Kev/CLM cards/repositories provide weights and code, but need independent same-workload comparisons with pinned versions, terms and realistic hardware. Laya weight/licence path and all base-model terms should be checked before publishing a licence conclusion. Avoid adopting self-reported “parity”/latency headlines.

• Route cost/terms: Vercel free-to-paid boundary, Netlify credit conversion, Cloudflare Jev dashboard rate, direct-account eligibility and all account-specific retention/credits need authenticated owner-approved checks. Recheck before any builder pilot; no real private payload in a test until terms are accepted.

• Monitoring: persist the exact daily 24h scan in PLAN.md/memory. A paid or owner-supplied X feed should supplement, not replace, primary verification. The next run should compare actual timestamps and release commits rather than treating newly discovered old repositories as new.
