Jev (TypeSafe AI) research report, 2 October 2026: model routing, the jev-mcp version check, and content moderation

This dated report records the evidence behind the release of 2 October 2026. The maintained pages built from it are: Jev Router or your own model router?, content moderation with Jev, the version check on Claude Code and MCP guardrails, and the refreshed home status and access status. Facts on those pages may be rechecked later; this report keeps the 2 October readings.

Run: run:8cfd1805-b04a-40d8-87dd-4c6c667c0920 (scheduled regular research run 5) · Pool: pool_jev_catalog · Runner: single agent · Checks: 2026-10-02, 05:13 to 05:28 UTC; runner started 05:12 and ended 05:38 UTC. Nothing slipped.

The run's full notes and its source ledger (66 sources, IDs R5-S01 to R5-S80: URL, access time, label, excerpt, outcome) are held in the pool's private record. Key sources are linked below and on the pages each finding feeds.

Rules kept: no account, key, purchase, inference call, weight download or third-party code execution. Third-party source was downloaded as text for reading only. Benchmark results are labelled Reported; nothing in this run is Tested. Search analytics were unavailable: the run input records the read-only analytics broker as not connected.

Previous release: regular-2026-10-01-data-privacy-alternatives; report: Laya vs Kev, data handling and ticket triage.

1. Summary answer, as of 2 October 2026

  1. Access is unchanged (checked 05:14 UTC). Signups are open with no new-user credit, as since 27 Sep, 22:33 UTC. The API is operational, as since 29 Sep, 22:05 UTC. The console still returns HTTP 403, so the pool did not observe signup. All four home notices are still current and kept; none retired, none added. Only the API's 90-day uptime figure moved (99.828% to 99.826%).
  2. Model routing: OpenRouter documents how its Jev Router narrows candidates, but not what it does when Jev fails, is unsure or gets a long conversation, nor how the routed model is billed. Of six self-hosted Jev routers read at pinned commits, one sends every Jev failure to its frontier model (gpt-6-astra); the other five keep the current model, fall back to a local scorer, or return no decision. Documented
  3. @jkudish/jev-mcp: 0.12.0 and 0.13.0 leave the audited failure path unchanged (advisory; malformed answers come back as "review"). Documented (source diff)
  4. Content moderation: of six Jev moderation projects read at pinned commits, four leave the post up or let it through when Jev fails, one holds it for a person (WordPress) and one returns no decision (a demo). Two have a pardon that lifts the punishment, but none restores a deleted message. No published moderation accuracy for Jev was found. Documented

use-cases/model-routing: meets the ship condition

  • OpenRouter's Jev Router docs read with explicit "not documented" results: on Jev failure, on long conversations and on routed-model billing, across four documents (docs page, model page and FAQ, llms.txt, the 4.16 MB full docs export).
  • Six routers read at pinned commits (condition: three or more), with what is sent to Jev, error handling and the failure destination filled from source for all six. Selection: LiteLLM plus the five highest-starred routers in a GitHub search for "jev model router" (313 results).
  • Counts: on a Jev error, 1 frontier tier, 1 keep current, 2 local scorer, 2 no decision. 4 of 6 act on confidence. 4 send the full ask with no length cut, 1 clips to 400 characters, 1 sends no prompt text.
  • Title query source: Bing and DuckDuckGo autocomplete suggest "jev router" for "jev r", "jev ro" and "jev routing" (05:15 UTC).

build/claude-code-mcp: version check done

  • 0.11.0 to 0.12.0: server code moved to a new file with tool logic byte-identical; rate-limit and outage results now come back as tool errors (still not an allow).
  • 0.12.0 to 0.13.0: jev_verify adds one Noul per claim and moves claim text into state; a repository example hook (not in the npm package) denies at block ≥ 0.85 and defers to the harness's permission prompt on any failure.

use-cases/content-moderation: meets the ship condition

  • Six projects read at pinned commits (condition: three or more), with thresholds, failure handling and reversal filled from source; five code-backed integrations and one runnable demo.

Evidence: TypeSafe's consistency cookbook measures repeatability on one post (90.8% label agreement; 99.2% with 74.2% automatic labels), not accuracy (Reported).
  • Title query source: independent publisher titles; no autocomplete suggestion for moderation on any endpoint (05:15 UTC).
