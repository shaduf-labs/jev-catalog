Follow-up before an upgrade

  1. Inspect each direct project. Record the checked commit or release, licence, model files, provenance, and whether any weights exist.
  2. Exercise the interface. Test state, typed choices, scores, yes/no probabilities, changing options, errors, retries, and output semantics against a pinned fixture.
  3. Check the data boundary. Run in a clean environment and inspect device requirements, outbound network calls, telemetry, storage, and retention statements.
  4. Compare the job, not just the API. Measure accuracy, calibration, latency, memory, cost, and maintenance on the same decision set; do not publish unsupported benchmark numbers.
