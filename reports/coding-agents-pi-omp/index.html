pi and omp: what happens when the Jev call fails

ohmyjev ships one Claude Code module and two adapters, for pi and for omp (oh-my-pi). Both adapters register a tool_call handler that sends Bash, write/edit and exfiltration-type calls to Jev through shared code, with a 1,500 ms timeout. When the call fails for any reason, the shared code returns nothing and the handler returns without blocking. pi's and oh-my-pi's extension docs say a tool_call handler "may block"; one that does not block lets the host run the tool. Documented

No API key
fail-open: the call throws and the gate lets the tool run; both adapters log "no Jev key: gates and screens let every call through".
Timeout or HTTP error
fail-open: 1,500 ms; same return.
Malformed answer
fail-open: the reply parser throws; same return.
Below threshold
acts-anyway: Bash is denied only at irreversible ≥ 0.6, irreversible with destructive intent ≥ 0.7 or exfiltration ≥ 0.7; writes only at secret ≥ 0.7 (secrets file ≥ 0.8).
Bypass
recorded: an off switch, read-only commands that skip Jev, each gate's own switch, and tools that are never sent to Jev.
Other handlers
Model routing, the done-check and (on omp) the subagent hook set no route, keep the model or do not block when Jev fails.

Because the Claude Code module was already one of the 80 on the failure map with the same terms, the map's ohmyjev row now names pi and omp instead of gaining a new row. One file reference in that row's bypass cell was corrected (runBrowse is in hooks/ohmyjev.ts L557–568, not in adapters/shared.ts).

Read but not settled: auto-mode and jcode

  • auto-mode 3.0.0 (Claude Code mod, published 20 Oct): its code replaces Claude Code's question with allow or deny; when Jev fails it keeps the question for you (as read: held with no key, on a 5,000 ms timeout, an HTTP error or a malformed answer; acts-anyway below a 0.2 block threshold). Not counted, because how the mod host handles its answer was not read in the host's own source, and the stages before Jev were not read line by line.
  • jcode (PR #1890, merged 19 Oct): makes three Jev models configurable. Jev chooses injected memories (none on an error), a browser action and a voice intent; no tool-call gate or model routing was found in the files read. Other callers were not read.
